# Amazon 欧洲多站点广告

## 目标

在不把欧洲当作单一市场的前提下，选择值得测试的站点、商品与季节窗口：先过合规/物流/本地化/经济性门槛，再按站点小预算验证，只有达到预注册条件才扩大。

开始前读 [references/source-and-guardrails.md](references/source-and-guardrails.md)。标准品与非标准品读 [references/standard-vs-nonstandard.md](references/standard-vs-nonstandard.md)，高客单和返校季读 [references/high-ticket-and-seasonal.md](references/high-ticket-and-seasonal.md)。

## 工作流

### 1. 建立站点 × ASIN 资格矩阵

逐站记录 seller/profile、marketplace、语言、币种、VAT/EPR/产品合规、可售 ASIN、Featured Offer、库存/配送、价格/促销、评价、退货、贡献毛利和广告产品可用性。任一关键项不明则该单元格 `HOLD`。

### 2. 判定商品决策类型

- `STANDARD`：规格、型号和比较标准较统一，跨站复用空间较大；
- `NONSTANDARD`：尺码、审美、场景、住宅/道路/气候或语言差异影响选择；
- `HIGH_TICKET`：不是只看标价，还要结合该品类决策周期、品牌信任和售后风险；
- `SEASONAL`：需求受当地学期、天气、节日或促销窗口影响。

同一商品可同时属于多个类型，例如高客单非标准季节品；计划要叠加相应护栏。

### 3. 选择测试站点

以当前证据评分：需求、竞争成本、毛利、库存/配送、合规、本地化完成度和可验证的受众/搜索词。课程中的流量成本、客单价或 ROAS uplift 只能作为研究假设，不能代替评分。

### 4. 本地化承接

对标题、关键词、图片/视频、单位、价格心理、信任标记、场景、尺码/兼容、配送与退货逐站审核。只有当前确认的认证或计划标识才能展示。

### 5. 建立站点独立测试

每个 marketplace 分开预算、币种、报告和归因。先用已验证的核心意图建立最小覆盖，再测试本地词、商品投放或受众。不要把 UK/DE 的 CVR 和 bid 直接复制成其它站点目标。

### 6. 按决策周期编排触点

高客单商品需要更长观察与品牌/规格验证；季节品按预热、峰值、长尾推进。只有当前账户可用时，才使用 SP/SB/SD/AMC 等具体能力。

### 7. 扩量或退出

预先定义贡献利润、CVR/ROAS、样本、库存、退货和归因成熟度门槛。扩量每次只改变一个主要变量；课程提到的增幅不是默认步长。失败站点保留证据并停在 `REJECTED_FOR_NOW`。

## 必须交付

- 站点 × ASIN 资格矩阵；
- 商品类型与本地化差异；
- 候选站点评分和拒绝理由；
- 逐站 PREHEAT / TEST / SCALE / EXIT 计划；
- 单变量实验、审批、预算上限和回退。
