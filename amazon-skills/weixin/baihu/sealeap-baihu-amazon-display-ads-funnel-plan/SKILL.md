# Amazon 展示广告漏斗计划

## 目标

按拉新、考虑、召回或复购目标选择展示广告定向和指标，用小预算对照测试证明增量，而不是把所有展示流量视为同一种转化来源。

## 适用任务

- 做当前状态的只读诊断。
- 形成有证据、可审批、可回退的计划或单变量实验。
- 判断信息不足时应继续验证、暂停还是保持 `HOLD`。

## 开始前要拿到

- 站点、广告账户可见的展示广告产品与定向选项。
- ASIN、受众、购买周期、复购周期、历史触点和一方基线。
- 贡献毛利、预算上限、归因窗口和品牌/效果目标。

缺少字段时明确标为 `UNKNOWN` 或 `NEEDS_EVIDENCE`，不要补造数据。

## 不可妥协的边界

- Amazon 当前官方规则、账户实时状态和一方业务报告优先；公开内容与第三方数据只能作为待验证启发或代理证据。
- 数值、政策、因果与执行状态分别标为 `FACT`、`ESTIMATE`、`ASSUMPTION` 或 `UNKNOWN`。
- 不捏造销量、搜索量、成本、产品属性、合规状态、评论、广告结果或平台机制。
- 默认提供诊断或草案。写入前展示对象、旧值、新值、影响、停止线与回退，核对用户已有授权是否覆盖对象、动作与预算；范围已明确授权时继续执行并回读核验，只有未覆盖或扩大的范围才请求批准。
- 不保存或输出素材来源身份、账号、链接、文章编号、发布日期、阅读量、原始话术或其他可反查线索。
- 平台界面、功能、费率、资格和规则会变化；执行前必须在目标站点复核。

## 工作流

1. 只选一个漏斗目标，并写出目标人群、期望行为和排除人群。
2. 核对账户当前可用的上下文、再营销、场内、兴趣、生活方式或自定义受众。
3. 把每个定向拆成独立可读单元，避免同时改变受众、创意、出价和落地页。
4. 为拉新、召回和复购分别选择指标，并记录归因窗口与自然基线。
5. 先窄后宽运行受控试点，达到样本门槛后再扩受众或预算。
6. 按约定目标复盘归因效率、新客、净贡献和频次；缺少有效对照时仅将增量结论标为 HOLD，不把归因销售宣称为新增销售。

## 判断规则

- 展示广告的界面、名称、库存和定向会变化，执行前以当前账户为准。
- 文章中的固定预算比例和优化周期只能作为假设，不能当作通用规则。
- 不得用受众属性推断敏感个人信息，也不得上传未经授权的客户数据。

## 必须交付的结果

- 漏斗目标与受众地图
- 分单元测试结构
- 指标及归因口径
- 扩量、降级和停止规则

结尾列出站点、数据窗口、口径、证据、关键假设、缺口、风险、下一步和所有待批准动作。证据不足时写 `HOLD`，不得包装成可直接执行。
