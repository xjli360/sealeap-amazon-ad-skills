# Amazon 大促广告就绪检查

## 目标

按活动日倒排商品、库存、优惠、关键词、素材和预算准备度，让已验证流量优先承担旺季目标，并给探索流量明确上限。

## 何时使用

- Prime Day、黑五网一或区域节日前的广告备战
- 需要区分新品、成熟品和清货品的旺季任务
- 担心预算提前耗尽、缺货或广告优惠信息不一致

## 开始前要拿到

- 站点、活动名称、日期、报名/优惠资格和官方活动日历
- ASIN 分层、库存覆盖、补货最迟日期、毛利与最低成交价
- 历史搜索词、位置、素材、CTR/CVR、广告销售和自然基线
- 预算上限、小时/日监控能力、停止和恢复负责人

缺失项必须标为 `UNKNOWN` 或 `NEEDS_EVIDENCE`；不得猜数字、补属性，或混用不同站点、ASIN、币种和时间窗。

## 不可妥协的边界

- 当前 Amazon 官方规则、目标账户实时状态和一方业务报告优先；公开内容与第三方数据只能作为待验证启发或代理证据。
- 默认提供诊断或草案。写入前展示对象、旧值、新值、影响、停止线与回退，核对用户已有授权是否覆盖对象、动作与预算；范围已明确授权时继续执行并回读核验，只有未覆盖或扩大的范围才请求批准。
- 数值、政策、因果和执行状态分别标为 `FACT`、`ESTIMATE`、`ASSUMPTION` 或 `UNKNOWN`。
- 不保存或输出素材来源身份、账号、链接、文章编号、发布日期、阅读量、原始话术或其他可反查线索。
- 用于归因比较的常规实验优先只改变一个主要变量，并保存可比基线；止损、合规修复与已授权回退可联动处理，记录全部变更并重建基线。
- 活动日期、资格、促销和广告产品以目标账户当前状态为准。
- 不得承诺自然排名、固定流量或复制个案的销量结果。
- 库存、价格与优惠不一致时，先修复承接条件，不用加预算掩盖。

## 工作流

1. 从活动日倒排资格、库存到仓、页面冻结、素材审核、测词和预算审批节点。
2. 按主推、守盘、探索、清货分层 ASIN，每层只设一个首要目标。
3. 成熟品优先使用已有转化证据的词和素材；新品把发现与验证预算隔离。
4. 核对广告、优惠、价格、库存和落地页信息在活动窗口内一致。
5. 按毛利、库存和目标订单定义日预算、位置出价、耗尽预警与停止线。
6. 活动中高频监控异常，活动后分阶段恢复预算并复盘增量、净贡献和库存结果。

## 判断状态

- `READY`：关键输入、资格与当前规则已核实，实验有预算、成功、停止和回退条件。
- `HOLD`：方向可能成立，但关键证据、样本或审批仍缺失。
- `STOP`：存在硬性违规、不可承受经济性、虚假声明或无法回退的风险。

## 必须交付的结果

- 活动倒排日历
- ASIN—目标—流量分层表
- 预算、库存和优惠联动表
- 实时监控与活动后恢复方案
- 数据范围、采集时间、定义、证据状态、限制和待批准动作
