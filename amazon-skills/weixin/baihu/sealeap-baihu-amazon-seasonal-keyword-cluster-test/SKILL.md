# Amazon 季节关键词组测试

## 目标

把热点词拆成同一季节购买意图下的核心词、修饰词和排除词，用独立预算验证相关性、承接和净贡献。

## 何时使用

- 节日、礼赠、返校、季节或天气需求的广告建词
- 一个关键词组包含大量近义和长尾变体
- 需要判断热点流量是否真的适合当前 ASIN

## 开始前要拿到

- 目标站点、当地语言、活动日期和需求起落窗口
- 产品事实、适用场景、不可支持的用途与落地页覆盖
- 一方搜索词、品牌分析、趋势或第三方代理及其采集日期
- 竞价、预算、毛利、库存、归因和最小样本门槛

缺失项必须标为 `UNKNOWN` 或 `NEEDS_EVIDENCE`；不得猜数字、补属性，或混用不同站点、ASIN、币种和时间窗。

## 不可妥协的边界

- 当前 Amazon 官方规则、目标账户实时状态和一方业务报告优先；公开内容与第三方数据只能作为待验证启发或代理证据。
- 默认提供诊断或草案。写入前展示对象、旧值、新值、影响、停止线与回退，核对用户已有授权是否覆盖对象、动作与预算；范围已明确授权时继续执行并回读核验，只有未覆盖或扩大的范围才请求批准。
- 数值、政策、因果和执行状态分别标为 `FACT`、`ESTIMATE`、`ASSUMPTION` 或 `UNKNOWN`。
- 不保存或输出素材来源身份、账号、链接、文章编号、发布日期、阅读量、原始话术或其他可反查线索。
- 用于归因比较的常规实验优先只改变一个主要变量，并保存可比基线；止损、合规修复与已授权回退可联动处理，记录全部变更并重建基线。
- 热点不等于相关；词组中的每个购买意图都要能由商品和页面真实承接。
- 不得堆砌关键词、滥用商标或用不支持的节日/人群声明获取曝光。
- 单个成功案例或固定订单数不能作为词组效果保证。

## 工作流

1. 定义活动、购买者、使用者、时间和任务，先写出允许与排除的意图。
2. 从一方搜索词开始扩展核心词、场景词、礼赠词和本地语言变体。
3. 按语义相关、证据强度和购买阶段聚类，去重并标记商标/合规风险。
4. 核对标题、要点、图片和落地页能否回答每个高优先级意图。
5. 按关键词组设置广告单元和成功线；SP 需要独立预算时拆分 campaign，避免同时改素材和竞价。
6. 用实际搜索词、转化、净贡献和季节衰减决定迁移、否定、暂停或复用。

## 判断状态

- `READY`：关键输入、资格与当前规则已核实，实验有预算、成功、停止和回退条件。
- `HOLD`：方向可能成立，但关键证据、样本或审批仍缺失。
- `STOP`：存在硬性违规、不可承受经济性、虚假声明或无法回退的风险。

## 必须交付的结果

- 季节意图与词组地图
- 相关性/页面承接检查
- 隔离测试结构和预算
- 搜索词回流与季后处置表
- 数据范围、采集时间、定义、证据状态、限制和待批准动作
