# Amazon 竞品价值地图

## 目标

按真实购买任务选择可比商品，分开事实、客户反馈和推断，识别可证明的价值缺口并形成自有验证计划。

## 何时使用

- 竞品很多但只会看 BSR、销量或功能参数
- 需要提炼产品、Listing 或广告差异方向
- 希望比较头部、主流和新品而不盲目照抄

## 开始前要拿到

- 目标细分、购买任务、价格带和本品事实
- 头部、主流、新品或替代方案的可比样本
- 详情页、价格、配送、评价、Q&A、广告可见度及采样时间
- 评论主题样本、退货/客服证据和自有单位经济

缺失项必须标为 `UNKNOWN` 或 `NEEDS_EVIDENCE`；不得猜数字、补属性，或混用不同站点、ASIN、币种和时间窗。

## 不可妥协的边界

- 当前 Amazon 官方规则、目标账户实时状态和一方业务报告优先；公开内容与第三方数据只能作为待验证启发或代理证据。
- 默认提供诊断或草案。写入前展示对象、旧值、新值、影响、停止线与回退，核对用户已有授权是否覆盖对象、动作与预算；范围已明确授权时继续执行并回读核验，只有未覆盖或扩大的范围才请求批准。
- 数值、政策、因果和执行状态分别标为 `FACT`、`ESTIMATE`、`ASSUMPTION` 或 `UNKNOWN`。
- 不保存或输出素材来源身份、账号、链接、文章编号、发布日期、阅读量、原始话术或其他可反查线索。
- 用于归因比较的常规实验优先只改变一个主要变量，并保存可比基线；止损、合规修复与已授权回退可联动处理，记录全部变更并重建基线。
- 不得复制竞品文案、图片、专利设计、商标或评论表达。
- BSR、第三方销量和前台广告观察都是代理，不能推断竞品真实销量、预算或匹配类型。
- 比较对象必须在用途、价格和成熟度上可解释，不能只挑支持结论的样本。

## 工作流

1. 定义购买任务和可比标准，再分层抽取头部、主流、新品与非 Amazon 替代方案。
2. 记录功能、证据、价格、优惠、配送、信任、内容和可见广告事实。
3. 对评论和 Q&A 做主题编码，标注样本、时间和正负反馈，避免摘句外推。
4. 把事实、客户声音和分析推断分栏，识别高频未满足任务与过度承诺。
5. 用本品能力、成本、合规和可证明性筛选机会，不复制竞品表达。
6. 为每个机会设计产品、内容或广告的最小验证和失败标准。

## 判断状态

- `READY`：关键输入、资格与当前规则已核实，实验有预算、成功、停止和回退条件。
- `HOLD`：方向可能成立，但关键证据、样本或审批仍缺失。
- `STOP`：存在硬性违规、不可承受经济性、虚假声明或无法回退的风险。

## 必须交付的结果

- 可比样本与选择理由
- 事实/反馈/推断价值地图
- 机会与不可做清单
- 自有产品和营销验证计划
- 数据范围、采集时间、定义、证据状态、限制和待批准动作
