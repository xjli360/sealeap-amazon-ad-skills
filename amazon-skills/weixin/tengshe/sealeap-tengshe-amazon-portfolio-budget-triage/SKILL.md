# Amazon 商品组合预算分诊

## 目标

停止平均撒预算，按商品贡献、证据、成熟度、库存和修复可行性分组，给少数可学习对象足够但有限的预算。

## 何时使用

- 店铺链接多、预算不足且整体 ACoS 过高
- 新品、成熟品和清货品争夺同一预算
- 频繁重开自动广告却没有有效学习

## 开始前要拿到

- ASIN/SKU、成熟度、价格、毛利、库存、补货与战略角色
- sessions、CVR、总订单、广告花费/订单、退货和页面质量
- 活动结构、搜索词、样本量、历史暂停/重开记录
- 总预算、最低学习成本、最大损失和团队修复能力

缺失项必须标为 `UNKNOWN` 或 `NEEDS_EVIDENCE`；不得猜数字、补属性，或混用不同站点、ASIN、币种和时间窗。

## 不可妥协的边界

- 当前 Amazon 官方规则、目标账户实时状态和一方业务报告优先；公开内容与第三方数据只能作为待验证启发或代理证据。
- 默认提供诊断或草案。写入前展示对象、旧值、新值、影响、停止线与回退，核对用户已有授权是否覆盖对象、动作与预算；范围已明确授权时继续执行并回读核验，只有未覆盖或扩大的范围才请求批准。
- 数值、政策、因果和执行状态分别标为 `FACT`、`ESTIMATE`、`ASSUMPTION` 或 `UNKNOWN`。
- 不保存或输出素材来源身份、账号、链接、文章编号、发布日期、阅读量、原始话术或其他可反查线索。
- 个案、论坛回答和示例 SQL 只能形成候选方法，不能证明普遍因果。
- 不得通过反复重建活动抹掉历史或把新活动误认为新机会。
- 低价、高 CPC 商品若经济性不成立，应修复产品/报价或退出，不靠更大预算。
- 预算分配同时考虑证据质量和学习价值，不只按过去销售奖励成熟品。

## 工作流

1. 统一商品级收入、贡献、库存、成熟度、广告和页面质量口径。
2. 把 ASIN 分为保护、证明、修复、收割/清货、退出，并写出证据。
3. 计算每个待证明商品达到最小学习样本的预算与最大可接受损失。
4. 优先保证保护和少量高价值验证，停止分散到无法学习的长尾。
5. 为修复组先解决页面、价格、评价基础、库存或产品问题，再重启有限测试。
6. 按固定节奏复盘迁移分组，保留暂停原因和历史，不以重建活动重置判断。

## 判断状态

- `READY`：当前规则、输入、基线和动作边界均已核实。
- `HOLD`：方向可能成立，但关键数据、样本、资格或审批仍缺失。
- `STOP`：存在违规、隐私越界、经济性不可承受、数据不可解释或无法回退。

## 必须交付的结果

- 商品组合分组与证据
- 学习预算和最大损失
- 保留/修复/暂停/退出动作表
- 周期迁移与历史日志
- 数据范围、采集时间、定义、证据状态、限制和待批准动作
