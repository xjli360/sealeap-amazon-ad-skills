# Amazon 每周运营节奏

## 目标

先处理账户、库存和利润异常，再以固定但可调整的周节奏复盘广告、内容和产品；每项工作都绑定阈值、负责人和决策。

## 何时使用

- 运营每天很忙但没有清楚产出
- 需要给多 ASIN 团队安排周会与例行检查
- 异常、优化和长期建设互相挤占

## 开始前要拿到

- 店铺/站点、ASIN 组合、季度目标和业务风险
- 账户健康、库存、利润、广告、页面、退货和客服看板
- 每项数据更新时间、阈值、负责人和升级路径
- 团队容量、会议时间、周期性截止和历史行动项

缺失项必须标为 `UNKNOWN` 或 `NEEDS_EVIDENCE`；不得猜数字、补属性，或混用不同站点、ASIN、币种和时间窗。

## 不可妥协的边界

- 当前 Amazon 官方规则、目标账户实时状态和一方业务报告优先；公开内容与第三方数据只能作为待验证启发或代理证据。
- 默认提供诊断或草案。写入前展示对象、旧值、新值、影响、停止线与回退，核对用户已有授权是否覆盖对象、动作与预算；范围已明确授权时继续执行并回读核验，只有未覆盖或扩大的范围才请求批准。
- 数值、政策、因果和执行状态分别标为 `FACT`、`ESTIMATE`、`ASSUMPTION` 或 `UNKNOWN`。
- 不保存或输出素材来源身份、账号、链接、文章编号、发布日期、阅读量、原始话术或其他可反查线索。
- 个案、论坛回答和示例 SQL 只能形成候选方法，不能证明普遍因果。
- 周一到周五的固定主题只是可配置模板，应按数据刷新和团队责任调整。
- 不以检查次数、改价次数或广告操作数衡量有效工作。
- 高风险异常优先于例行优化，任何线上动作仍需审批和回退。

## 工作流

1. 定义账户健康、缺货、亏损、异常花费和合规的日常红线及负责人。
2. 建立每日短巡检，只处理越线例外并记录原因，不重复浏览全部报表。
3. 每周统一复盘利润、广告、库存、Listing/客户信号和产品机会。
4. 将分析转成少量有对象、依据、负责人、期限和停止线的行动。
5. 保留一段无会议深度工作，减少为忙而忙的低价值操作。
6. 下周先检查旧行动结果、偏差和未决问题，再生成新任务和升级项。

## 判断状态

- `READY`：当前规则、输入、基线和动作边界均已核实。
- `HOLD`：方向可能成立，但关键数据、样本、资格或审批仍缺失。
- `STOP`：存在违规、隐私越界、经济性不可承受、数据不可解释或无法回退。

## 必须交付的结果

- 日常异常阈值与升级表
- 每周议程和数据刷新表
- 决策/行动/负责人日志
- 低价值工作停止清单
- 数据范围、采集时间、定义、证据状态、限制和待批准动作
