# Amazon 市场可运营性门

## 目标

需求和竞争只是起点；把产品购买理由、信任门槛、供应合规、单位经济和团队执行能力放进同一进入决策。

## 何时使用

- 纠结蓝海或红海类目是否值得进入
- 选品数据好但不知道团队能否做成
- 需要识别产品失败是市场、信任还是执行问题

## 开始前要拿到

- 站点、购买任务、关键词需求和趋势代理
- 可比商品、价格、评价、品牌集中和进入变化
- 本品差异、证明、信任资产、供应、合规与知识产权
- 落地成本、广告、退货、库存、现金周期和团队能力

缺失项必须标为 `UNKNOWN` 或 `NEEDS_EVIDENCE`；不得猜数字、补属性，或混用不同站点、ASIN、币种和时间窗。

## 不可妥协的边界

- 当前 Amazon 官方规则、目标账户实时状态和一方业务报告优先；公开内容与第三方数据只能作为待验证启发或代理证据。
- 默认提供诊断或草案。写入前展示对象、旧值、新值、影响、停止线与回退，核对用户已有授权是否覆盖对象、动作与预算；范围已明确授权时继续执行并回读核验，只有未覆盖或扩大的范围才请求批准。
- 数值、政策、因果和执行状态分别标为 `FACT`、`ESTIMATE`、`ASSUMPTION` 或 `UNKNOWN`。
- 不保存或输出素材来源身份、账号、链接、文章编号、发布日期、阅读量、原始话术或其他可反查线索。
- 个案、论坛回答和示例 SQL 只能形成候选方法，不能证明普遍因果。
- “蓝海/红海”只是标签，不可替代细分购买任务和真实经济性。
- 第三方销量、搜索量和竞争指数均为估算，必须给来源、窗口和误差。
- 市场看似空白可能源于低需求、法规、供应或体验难题，不能自动视为机会。

## 工作流

1. 从具体购买任务、使用者、场景和价格带定义可比市场。
2. 验证需求规模、趋势、季节和替代方案，并记录第三方证据边界。
3. 写出本品为何值得买、如何证明、需要跨越的评价/品牌/内容信任门槛。
4. 模拟竞品降价、复制、广告加剧和供应波动，测试差异的可防守性。
5. 重算 landed cost、广告、退货、库存和现金周期，并核对团队执行缺口。
6. 按进入、有限验证、等待或退出给结论，关键证据缺失时保持 HOLD。

## 判断状态

- `READY`：当前规则、输入、基线和动作边界均已核实。
- `HOLD`：方向可能成立，但关键数据、样本、资格或审批仍缺失。
- `STOP`：存在违规、隐私越界、经济性不可承受、数据不可解释或无法回退。

## 必须交付的结果

- 细分市场与需求证据
- 购买理由和信任门槛
- 竞争响应与执行能力表
- 单位经济、下行情景和进入决策
- 数据范围、采集时间、定义、证据状态、限制和待批准动作
