# Amazon 电商设计 KPI 评分卡

## 目标

把设计可控的准确性、信息层级、移动端可读性、合规和交付质量，与运营共同承担的实验和业务结果分开评价。

## 何时使用

- 讨论美工是否应该背点击率或转化率
- 创意团队只看审美或只背销售结果
- 需要建立设计复盘、培训和跨职能责任

## 开始前要拿到

- 设计岗位职责、可控范围、brief、交付流程和审核记录
- 素材版本、位置、流量来源、价格、评价和同期运营变更
- CTR、CVR、退货、审核拒绝、返工和交付周期
- 实验设计、样本、归因、团队目标和各岗位责任

缺失项必须标为 `UNKNOWN` 或 `NEEDS_EVIDENCE`；不得猜数字、补属性，或混用不同站点、ASIN、流量来源和时间窗。

## 不可妥协的边界

- 当前 Amazon 官方规则、目标账户实时状态、真实产品证据和一方业务报告优先；公开内容与第三方数据只能作为待验证启发。
- 默认提供诊断或草案。写入前展示对象、旧值、新值、影响、停止线与回退，核对用户已有授权是否覆盖对象、动作与预算；范围已明确授权时继续执行并回读核验，只有未覆盖或扩大的范围才请求批准。
- 数值、政策、因果和执行状态分别标为 `FACT`、`ESTIMATE`、`ASSUMPTION` 或 `UNKNOWN`。
- 不保存或输出素材来源身份、账号、链接、文章编号、发布日期、阅读量、原始话术、图片或其他可反查线索。
- 不复制他人文案、图片或品牌表达；输出必须基于当前商品重新设计。
- 设计师不能独自控制流量、竞价、价格、评价、库存和产品，因此不得单独承担原始 CVR/销量。
- CTR 必须按广告位置、查询、人群和素材版本归一；不同上下文不能横比。
- 评分卡用于改进和协作，不应用单次波动惩罚个人。

## 工作流

1. 列出设计师可直接控制、共同影响和完全不可控的因素。
2. 建立事实准确、信息层级、移动端可读、品牌一致、合规、版本管理等过程指标。
3. 为 CTR/CVR/退货等共享结果记录位置、流量、报价、样本和共同负责人。
4. 把每个创意任务转成可检验 brief，并在发布前做跨职能 QA。
5. 用单变量实验和足够窗口评价版本，不用一次活动结果做个人结论。
6. 按月复盘重复错误、有效模式和培训需求，调整权重但保留历史版本。

## 判断状态

- `READY`：产品事实、规则、基线和测试方法均已核实。
- `HOLD`：方向可能成立，但买家证据、产品证明、样本或审批仍缺失。
- `STOP`：内容误导、侵权、违规、单位经济不可承受或无法回退。

## 必须交付的结果

- 控制权与责任矩阵
- 过程质量和共享结果评分卡
- 素材实验与归因规则
- 复盘、培训和权重调整记录
- 数据范围、采集时间、证据状态、限制和待批准动作
