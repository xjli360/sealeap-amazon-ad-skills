# Amazon 图片构图转化测试

## 目标

让一张图只承担一个购买问题，用真实比例、明确层级和可证明信息设计构图，并在移动端做单变量转化测试。

## 何时使用

- 想用一个作图技巧提升理解或转化
- 附图信息太多、层级混乱或移动端看不清
- 需要把设计建议变成可归因实验

## 开始前要拿到

- ASIN、站点、当前图片序列和类目图片规则
- 目标买家问题、产品事实、尺寸比例、随附物和证据
- 移动端/桌面缩略图、基线点击/转化/退货反馈
- 候选构图、唯一主要变量、测试窗口和样本门槛

缺失项必须标为 `UNKNOWN` 或 `NEEDS_EVIDENCE`；不得猜数字、补属性，或混用不同站点、ASIN、流量来源和时间窗。

## 不可妥协的边界

- 当前 Amazon 官方规则、目标账户实时状态、真实产品证据和一方业务报告优先；公开内容与第三方数据只能作为待验证启发。
- 默认提供诊断或草案。写入前展示对象、旧值、新值、影响、停止线与回退，核对用户已有授权是否覆盖对象、动作与预算；范围已明确授权时继续执行并回读核验，只有未覆盖或扩大的范围才请求批准。
- 数值、政策、因果和执行状态分别标为 `FACT`、`ESTIMATE`、`ASSUMPTION` 或 `UNKNOWN`。
- 不保存或输出素材来源身份、账号、链接、文章编号、发布日期、阅读量、原始话术、图片或其他可反查线索。
- 不复制他人文案、图片或品牌表达；输出必须基于当前商品重新设计。
- 不得改变产品真实比例、颜色、数量、包装内容或暗示未包含配件。
- 主图与附图规则不同；任何构图方案先确认目标位置当前政策。
- 设计技巧不是因果保证，只有可比实验能判断对当前 ASIN 的作用。

## 工作流

1. 从评论、Q&A、退货或客服选一个高优先级购买疑问。
2. 确定这张图唯一要表达的答案、证据和不能暗示的内容。
3. 用主体、对比、留白、阅读路径和真实尺度建立视觉层级。
4. 在手机缩略图和详情页尺寸检查文字、顺序、颜色和产品识别。
5. 只改变一个构图变量制作对照版本，其他文案、流量和报价保持稳定。
6. 按理解、CTR/CVR、净贡献和退货反证判断，保留版本与回退。

## 判断状态

- `READY`：产品事实、规则、基线和测试方法均已核实。
- `HOLD`：方向可能成立，但买家证据、产品证明、样本或审批仍缺失。
- `STOP`：内容误导、侵权、违规、单位经济不可承受或无法回退。

## 必须交付的结果

- 买家问题与图片任务卡
- 构图、比例和声明 QA
- 移动端预览记录
- 单变量版本与测试结论
- 数据范围、采集时间、证据状态、限制和待批准动作
