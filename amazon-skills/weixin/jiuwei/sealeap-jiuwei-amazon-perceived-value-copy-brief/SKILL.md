# Amazon 感知价值文案简报

## 目标

把产品事实依次连接到优势、客户结果和证明，用高感知表达降低理解成本，但所有体验词都受证据与适用条件约束。

## 何时使用

- 文案只有参数、买家难以理解价值
- 想使用 FAB 或更有画面感的表达
- 需要统一 Listing、图片、A+ 和广告的主张

## 开始前要拿到

- 产品规格、检测、材料、使用限制和证据文件
- 目标购买任务、真实买家问题、退货和客服原因
- 当前标题、要点、图片、A+、广告和移动端截图
- 竞品只作事实比较，另有商标、类目和声明规则

缺失项必须标为 `UNKNOWN` 或 `NEEDS_EVIDENCE`；不得猜数字、补属性，或混用不同站点、ASIN、流量来源和时间窗。

## 不可妥协的边界

- 当前 Amazon 官方规则、目标账户实时状态、真实产品证据和一方业务报告优先；公开内容与第三方数据只能作为待验证启发。
- 默认提供诊断或草案。写入前展示对象、旧值、新值、影响、停止线与回退，核对用户已有授权是否覆盖对象、动作与预算；范围已明确授权时继续执行并回读核验，只有未覆盖或扩大的范围才请求批准。
- 数值、政策、因果和执行状态分别标为 `FACT`、`ESTIMATE`、`ASSUMPTION` 或 `UNKNOWN`。
- 不保存或输出素材来源身份、账号、链接、文章编号、发布日期、阅读量、原始话术、图片或其他可反查线索。
- 不复制他人文案、图片或品牌表达；输出必须基于当前商品重新设计。
- 感官、情绪、比较和结果表达必须可由产品事实支持，不能创造不存在的体验。
- 不得使用无法证明的最佳、唯一、绝对安全、医学或环保声明。
- FAB 链中任一环缺证据，该整条主张保持 HOLD 或降级。

## 工作流

1. 列出不可变产品事实、适用条件、限制和证据编号。
2. 为每个事实写出机制优势、客户结果和最强可用证明，形成 F-A-B-P 链。
3. 按购买决策优先级排序，只保留能解决主要疑问的少量主张。
4. 将抽象结果改写为可理解场景或感受，同时保留条件和准确尺度。
5. 分别适配标题、要点、图片、A+ 和广告，保证跨触点一致。
6. 在移动端做可读性审查并以单变量版本测试理解、转化和退货反馈。

## 判断状态

- `READY`：产品事实、规则、基线和测试方法均已核实。
- `HOLD`：方向可能成立，但买家证据、产品证明、样本或审批仍缺失。
- `STOP`：内容误导、侵权、违规、单位经济不可承受或无法回退。

## 必须交付的结果

- 事实—优势—结果—证明矩阵
- 主张优先级与禁用词
- 各触点文案简报
- 移动端 QA 和单变量测试
- 数据范围、采集时间、证据状态、限制和待批准动作
