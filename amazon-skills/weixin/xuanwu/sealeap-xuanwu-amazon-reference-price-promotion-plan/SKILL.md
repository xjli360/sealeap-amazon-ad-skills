# Amazon 参考价与促销计划

## 目标

在当前站点规则和真实成交历史约束下安排促销，避免因参考价不可用、折扣叠加或虚高历史价格造成资格、利润与合规风险。

## 适用任务

- 做当前状态的只读诊断。
- 形成有证据、可审批、可回退的计划或单变量实验。
- 判断信息不足时应继续验证、暂停还是保持 `HOLD`。

## 开始前要拿到

- 站点、ASIN、当前价、真实成交价历史和可见参考价状态。
- 计划中的 Deal、Coupon、企业价、会员价及其叠加关系。
- 贡献毛利、促销费用、库存、活动窗口和最低可接受净利。

缺少字段时明确标为 `UNKNOWN` 或 `NEEDS_EVIDENCE`，不要补造数据。

## 不可妥协的边界

- Amazon 当前官方规则、账户实时状态和一方业务报告优先；公开内容与第三方数据只能作为待验证启发或代理证据。
- 数值、政策、因果与执行状态分别标为 `FACT`、`ESTIMATE`、`ASSUMPTION` 或 `UNKNOWN`。
- 不捏造销量、搜索量、成本、产品属性、合规状态、评论、广告结果或平台机制。
- 默认提供诊断或草案。写入前展示对象、旧值、新值、影响、停止线与回退，核对用户已有授权是否覆盖对象、动作与预算；范围已明确授权时继续执行并回读核验，只有未覆盖或扩大的范围才请求批准。
- 不保存或输出素材来源身份、账号、链接、文章编号、发布日期、阅读量、原始话术或其他可反查线索。
- 平台界面、功能、费率、资格和规则会变化；执行前必须在目标站点复核。

## 工作流

1. 先查目标站点最新官方规则与后台资格，记录生效日期和参考价类型。
2. 导出足够长的真实成交历史，标记促销、优惠券、企业订单、异常订单和调价。
3. 分别计算候选促销价的展示资格、折扣深度、单位净贡献和库存影响。
4. 检查不同促销工具是否可叠加以及顾客实际支付价，不凭旧经验推断。
5. 形成不改变历史真实性的价格日历，并设置资格消失或毛利穿透时的停止条件。
6. 发布前再次核对后台预览；只在明确批准后创建或修改促销。

## 判断规则

- 历史售价与典型价格的计算和显示可能变化，以当前官方说明和后台为准。
- 不得先抬价再打折、制造虚假参考价或用异常订单塑造历史价格。
- 看不到参考价时标为 UNKNOWN，不保证某次调价能恢复展示。

## 必须交付的结果

- 参考价证据时间线
- 促销叠加与净价矩阵
- 价格日历草案
- 资格、利润与库存风险清单

结尾列出站点、数据窗口、口径、证据、关键假设、缺口、风险、下一步和所有待批准动作。证据不足时写 `HOLD`，不得包装成可直接执行。
