# Amazon FBA 入库方案选择

## 目标

在同一时点捕获所有可选入库方案，用总成本、到仓时效和断货风险而非单一费用选择方案，并确保完整执行所选拆分。

## 何时使用

- Send to Amazon 出现多个地点、费用和时效选项
- 旺季担心拥堵、接收延迟或断货
- 需要比较最少拆分、部分拆分或优化拆分

## 开始前要拿到

- 站点、货件计划、SKU/箱规/数量和所有当前可选方案快照
- 入库配置费、预估运输费、标签/操作费和承运商报价
- 各目的地接收提示、预约、运输和历史入库时长
- 可售库存、销量预测、安全库存、毛利与缺货损失

缺失项必须标为 `UNKNOWN` 或 `NEEDS_EVIDENCE`；不得猜数字、补属性，或混用不同站点、ASIN、币种和时间窗。

## 不可妥协的边界

- 当前 Amazon 官方规则、目标账户实时状态和一方业务报告优先；公开内容与第三方数据只能作为待验证启发或代理证据。
- 默认提供诊断或草案。写入前展示对象、旧值、新值、影响、停止线与回退，核对用户已有授权是否覆盖对象、动作与预算；范围已明确授权时继续执行并回读核验，只有未覆盖或扩大的范围才请求批准。
- 数值、政策、因果和执行状态分别标为 `FACT`、`ESTIMATE`、`ASSUMPTION` 或 `UNKNOWN`。
- 不保存或输出素材来源身份、账号、链接、文章编号、发布日期、阅读量、原始话术或其他可反查线索。
- 可用选项、容量提示、费率和到仓时间都是时点信息，不得视为保证。
- 确认拆分方案后必须完成计划内所有货件；放弃部分货件可能触发重算或缺陷费用。
- 比较必须使用相同数量、箱规、币种和费用边界。

## 工作流

1. 在同一货件计划和时间点保存所有选项、目的地、费用与时效快照。
2. 把运输、配置、操作、预约、延误和缺货机会成本归一到同一口径。
3. 检查每个方案的箱规、最低要求、容量提示和全部货件完成义务。
4. 按成本、到仓风险、库存紧迫度和执行复杂度做情景比较。
5. 选择方案前记录理由、假设、承运与预约计划，并锁定负责人。
6. 发出后跟踪每票接收、最终费用和偏差，用实绩校准下一次决策。

## 判断状态

- `READY`：关键输入、资格与当前规则已核实，方案有成功、停止和回退条件。
- `HOLD`：方向可能成立，但关键证据或审批仍缺失。
- `STOP`：存在硬性违规、不可承受的经济性、虚假信息或无法回退的风险。

## 必须交付的结果

- 同口径入库选项比较表
- 成本、时效和断货情景
- 确认与全部货件执行清单
- 接收偏差和费用复盘
- 数据范围、采集时间、定义、证据状态、限制和待批准动作
