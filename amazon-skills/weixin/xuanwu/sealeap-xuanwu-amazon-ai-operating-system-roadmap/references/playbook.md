# Amazon AI 运营系统路线图执行手册

## 工作表

| 阶段 | 必须记录 | 通过条件 |
|---|---|---|
| 流程盘点 | 任务、负责人、耗时、等待、错误成本 | 基线可量化且痛点由流程证据支持 |
| 风险分级 | 读取、分析、草案、写入及数据敏感度 | 权限最小化，高风险动作有人审 |
| 试点设计 | 输入契约、金标样本、质量门、回退 | 只选一个低风险高价值用例 |
| 验收 | 准确率、节省时间、返工率、业务指标 | 效率与业务结果分别报告 |

## 证据台账字段

- `claim`：当前要支持或反驳的判断。
- `status`：`FACT`、`ESTIMATE`、`ASSUMPTION` 或 `UNKNOWN`。
- `source_type`：Amazon 一方、账户一方、第三方代理、公开观察或用户输入。
- `marketplace/window/sample`：站点、时间窗和样本量。
- `value/unit/definition`：数值、单位和字段定义。
- `limitations`：缺失、延迟、归因、选择偏差和可能的反向解释。
- `decision/owner/next_check`：当前决定、责任人和复核点。

## 指标与计算

- 覆盖率、字段准确率、严重错误率和人工接受率。
- 单任务人工分钟数、返工分钟数与总节省时间。
- 审计日志完整率、失败恢复时间和越权事件数。

公式必须展示输入、单位和窗口；任何经验阈值都标为团队可调参数，并给出悲观、基准和乐观情景。

## 状态门

- `READY`：关键输入完整，政策和账户资格已核实，实验有预算、停止线和回退。
- `HOLD`：方向可能成立，但一个或多个关键证据仍缺失。
- `STOP`：出现硬性违规、不可承受经济性或无法回退的风险。

立即 `STOP` 的典型条件：

- 输入数据无合法权限或边界不清。
- 输出不能追溯到输入与证据。
- 严重错误或人工返工超过预设门槛。

## 质量检查

- 当前规则与账户状态的检查日期明确；旧截图和旧经验不能冒充当前事实。
- 所有表格使用相同站点、货币、时区、父子体、归因和统计窗口。
- 没有把平台总体数据、第三方估算、个案或相关性写成自身确定结果。
- 草案与实际写入分开；实际变更前展示对象、旧值、新值、影响和回退，确认已有授权覆盖后执行并回读核验；新增范围才另行请求批准。
- 复盘同时呈现成功指标、反证、干扰变量和样本限制。

## 交付模板

1. 任务、站点、对象与时间窗
2. 证据台账与数据口径
3. 诊断或假设
4. 方案/实验及敏感性情景
5. 风险、停止线和回退
6. `READY`、`HOLD` 或 `STOP` 结论
7. 下一步、负责人和待批准动作
