# Amazon 受限商品响应

## 目标

保存原始通知，区分商品本体、类目资格、法律要求和页面声明问题，以真实证据决定整改、争议或停止销售。

## 何时使用

- 收到受限商品、合规文件或账号健康通知
- 商品或详情页因声明、成分、用途或监管分类被移除
- 需要形成申诉证据包和整改顺序

## 开始前要拿到

- 完整绩效通知、ASIN/SKU、站点、时间和案例编号
- 商品成分、规格、包装、标签、供应链与检测/许可原件
- 当前详情页、图片、广告、关键词和历史修改记录
- 适用法律、监管分类、Amazon 当前政策及专业意见

缺失项必须标为 `UNKNOWN` 或 `NEEDS_EVIDENCE`；不得猜数字、补属性，或混用不同站点、ASIN、币种和时间窗。

## 不可妥协的边界

- 当前 Amazon 官方规则、目标账户实时状态和一方业务报告优先；公开内容与第三方数据只能作为待验证启发或代理证据。
- 默认提供诊断或草案。写入前展示对象、旧值、新值、影响、停止线与回退，核对用户已有授权是否覆盖对象、动作与预算；范围已明确授权时继续执行并回读核验，只有未覆盖或扩大的范围才请求批准。
- 数值、政策、因果和执行状态分别标为 `FACT`、`ESTIMATE`、`ASSUMPTION` 或 `UNKNOWN`。
- 不保存或输出素材来源身份、账号、链接、文章编号、发布日期、阅读量、原始话术或其他可反查线索。
- 这是高风险合规流程；法律或监管判断必须由合格专业人士确认。
- 严禁伪造、修改、借用检测报告、发票、证书或供应商身份。
- 不得换 ASIN、换店或改写名称来绕过限制；确认禁止销售时应停止并处理库存风险。

## 工作流

1. 原样保存通知、违规类型、截止时间、受影响对象和当前页面快照。
2. 把问题拆为商品禁止、类目受限、文件缺失、标签/声明问题或可能误判。
3. 逐条比对目标市场法律、监管要求和 Amazon 当前政策，标注适用范围与日期。
4. 建立主张—证据矩阵；缺少原始证据的主张删除或保持 UNKNOWN。
5. 事实支持合规时起草简洁争议说明；事实不支持时先整改商品、页面或停售方案。
6. 由合规/法务复核后提交，并保存提交版本、回执、补件和最终处置。

## 判断状态

- `READY`：关键输入、资格与当前规则已核实，方案有成功、停止和回退条件。
- `HOLD`：方向可能成立，但关键证据或审批仍缺失。
- `STOP`：存在硬性违规、不可承受的经济性、虚假信息或无法回退的风险。

## 必须交付的结果

- 通知与截止时间台账
- 政策和监管适用矩阵
- 主张—证据包及缺口
- 整改/申诉草案、负责人和停止线
- 数据范围、采集时间、定义、证据状态、限制和待批准动作
