# Amazon 部分退款决策

## 目标

先确认订单类型和当前可用方案，再比较客户结果、逆向物流、残值、欺诈风险与合规成本，形成有阈值的退款决策。

## 何时使用

- 退回商品残值低、运输或处理成本高
- 考虑部分退款、退款不退货或换货
- 需要为不同退货原因和价格带建立审批规则

## 开始前要拿到

- 市场、FBA/MFN、订单状态、ASIN 与当前账户可用退款选项
- 退货原因、客户请求、商品状态、售价和税费
- 退运、处理、检验、翻新、仓储、移除与残值
- 退货滥用信号、客服历史和适用消费者保护要求

缺失项必须标为 `UNKNOWN` 或 `NEEDS_EVIDENCE`；不得猜数字、补属性，或混用不同站点、ASIN、币种和时间窗。

## 不可妥协的边界

- 当前 Amazon 官方规则、目标账户实时状态和一方业务报告优先；公开内容与第三方数据只能作为待验证启发或代理证据。
- 默认提供诊断或草案。写入前展示对象、旧值、新值、影响、停止线与回退，核对用户已有授权是否覆盖对象、动作与预算；范围已明确授权时继续执行并回读核验，只有未覆盖或扩大的范围才请求批准。
- 数值、政策、因果和执行状态分别标为 `FACT`、`ESTIMATE`、`ASSUMPTION` 或 `UNKNOWN`。
- 不保存或输出素材来源身份、账号、链接、文章编号、发布日期、阅读量、原始话术或其他可反查线索。
- 客户合法退款和退货权利优先；不得用部分退款施压、误导或阻碍正当救济。
- FBA 与卖家自配送的权限、责任和偿付规则不同，必须分开。
- 自动规则只在当前资格和可承受阈值内使用，并定期审计异常和偏差。

## 工作流

1. 确认订单履约方式、状态、退货原因和当前账户实际可用选项。
2. 按全退、部分退、退款不退货、换货和收回商品计算客户与商家总成本。
3. 核对商品安全、召回、监管、卫生和高欺诈风险是否排除自动处理。
4. 按价格带、原因、残值和滥用证据定义建议方案与人工审批阈值。
5. 用小范围订单回测客户结果、净回收、投诉和误判，避免只看退款金额。
6. 上线后保留逐单理由、责任人和例外，并在政策或结果变化时停用规则。

## 判断状态

- `READY`：关键输入、资格与当前规则已核实，方案有成功、停止和回退条件。
- `HOLD`：方向可能成立，但关键证据或审批仍缺失。
- `STOP`：存在硬性违规、不可承受的经济性、虚假信息或无法回退的风险。

## 必须交付的结果

- 资格与责任矩阵
- 多方案期望成本比较
- 自动/人工阈值及例外
- 试点、审计和客户沟通草案
- 数据范围、采集时间、定义、证据状态、限制和待批准动作
