# Amazon 变体主题迁移

## 目标

在不制造虚假变体关系、不中断有效子体销售的前提下，判断现有家族应保持、修复还是迁移，并形成可回退的分批操作方案。

## 何时使用

- 后台提示变体主题已弃用或指定值无效
- 计划更新父子体但担心家族拆散、评价或库存受影响
- 需要核对类目模板里的当前有效主题

## 开始前要拿到

- marketplace、product type、父 SKU、子 SKU/ASIN 与当前主题的完整快照
- 当前类目模板、可选主题、报错文本和采集时间
- 各子体的真实差异属性、库存、在售状态和详情页证据
- 计划修改的字段、批次、低流量窗口和回退负责人

缺失项必须标为 `UNKNOWN` 或 `NEEDS_EVIDENCE`；不得猜数字、补属性，或混用不同站点、ASIN、币种和时间窗。

## 不可妥协的边界

- 当前 Amazon 官方规则、目标账户实时状态和一方业务报告优先；公开内容与第三方数据只能作为待验证启发或代理证据。
- 默认提供诊断或草案。写入前展示对象、旧值、新值、影响、停止线与回退，核对用户已有授权是否覆盖对象、动作与预算；范围已明确授权时继续执行并回读核验，只有未覆盖或扩大的范围才请求批准。
- 数值、政策、因果和执行状态分别标为 `FACT`、`ESTIMATE`、`ASSUMPTION` 或 `UNKNOWN`。
- 不保存或输出素材来源身份、账号、链接、文章编号、发布日期、阅读量、原始话术或其他可反查线索。
- 不得为了共享评价或流量而合并不同产品；每个子体必须真实符合所选变体维度。
- 不要因旧主题出现在历史家族中就擅自删除父体；先确认当前通知、模板与实际更新需求。
- 涉及删除或重建父体时必须先导出映射和原值，并在小批量验证后再扩大。

## 工作流

1. 冻结当前父子关系、主题、属性、SKU/ASIN、库存与前台展示快照。
2. 下载目标站点当前模板，把主题分为仍有效、已弃用、未知三类，并保存证据日期。
3. 区分无需更新且仍正常的家族，与必须改动或已报错的家族；未知项保持 HOLD。
4. 把每个子体映射到一个真实且当前有效的差异维度，生成旧值、新值和不可迁移项。
5. 先在低风险家族或最小批次执行草案，核对父子关系、可售状态、详情页与搜索后再继续。
6. 若出现子体孤立、属性丢失、库存异常或页面错误，立即停止；仅恢复仍符合当前主题规则的已知有效映射，弃用主题不能盲目回填，无法安全恢复时升级人工支持。

## 判断状态

- `READY`：关键输入、资格与当前规则已核实，方案有成功、停止和回退条件。
- `HOLD`：方向可能成立，但关键证据或审批仍缺失。
- `STOP`：存在硬性违规、不可承受的经济性、虚假信息或无法回退的风险。

## 必须交付的结果

- 家族影响清单与证据状态
- 旧主题到新主题的逐 SKU 映射
- 分批操作、验证与回退运行表
- 无法安全迁移的 HOLD 清单
- 数据范围、采集时间、定义、证据状态、限制和待批准动作
