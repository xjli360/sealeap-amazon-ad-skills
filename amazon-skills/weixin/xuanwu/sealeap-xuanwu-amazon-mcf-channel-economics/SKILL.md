# Amazon MCF 渠道经济性

## 目标

把多渠道履约从功能宣传变成逐渠道单位经济、时效、包装、库存和退货验证，先小规模试点再决定扩量。

## 何时使用

- 独立站、社媒店铺或其他平台考虑接入 MCF
- 需要比较 MCF、3PL 和自发货的总成本与承诺
- 担心共享 FBA 库存导致缺货或渠道体验不一致

## 开始前要拿到

- 目标国家、销售渠道及其履约/包装/追踪规则
- SKU 尺寸重量、订单件数分布、当前 MCF 费率与服务级别
- FBA 可用库存、Amazon 站内需求、补货周期和安全库存
- 取消、退货、客服、集成与异常订单成本

缺失项必须标为 `UNKNOWN` 或 `NEEDS_EVIDENCE`；不得猜数字、补属性，或混用不同站点、ASIN、币种和时间窗。

## 不可妥协的边界

- 当前 Amazon 官方规则、目标账户实时状态和一方业务报告优先；公开内容与第三方数据只能作为待验证启发或代理证据。
- 默认提供诊断或草案。写入前展示对象、旧值、新值、影响、停止线与回退，核对用户已有授权是否覆盖对象、动作与预算；范围已明确授权时继续执行并回读核验，只有未覆盖或扩大的范围才请求批准。
- 数值、政策、因果和执行状态分别标为 `FACT`、`ESTIMATE`、`ASSUMPTION` 或 `UNKNOWN`。
- 不保存或输出素材来源身份、账号、链接、文章编号、发布日期、阅读量、原始话术或其他可反查线索。
- 费率、服务时效、承运商、包装和渠道兼容性必须按当前国家与账户核验。
- 不得只比较拣配费；必须纳入仓储、退货、缺货、集成和客户承诺成本。
- 共享库存前设置 Amazon 与外部渠道的安全库存和优先级，避免一端销售挤占另一端。

## 工作流

1. 确认目标渠道允许的履约商、追踪、包装和服务承诺。
2. 按当前费率卡计算订单件数、尺寸级别和服务速度下的全成本。
3. 把 MCF 与现有 3PL/自发货按相同订单结构、退货和异常口径比较。
4. 建立共享库存分配、安全库存、补货和缺货降级规则。
5. 验证下单集成、取消、追踪、客服、退货与品牌体验端到端流程。
6. 选少量 SKU/地区试点，以准时率、完整率、净贡献和客服异常决定扩大。

## 判断状态

- `READY`：关键输入、资格与当前规则已核实，方案有成功、停止和回退条件。
- `HOLD`：方向可能成立，但关键证据或审批仍缺失。
- `STOP`：存在硬性违规、不可承受的经济性、虚假信息或无法回退的风险。

## 必须交付的结果

- 渠道资格与体验差异表
- 逐订单/逐件单位经济模型
- 库存与异常路由规则
- 试点、监控和退出方案
- 数据范围、采集时间、定义、证据状态、限制和待批准动作
