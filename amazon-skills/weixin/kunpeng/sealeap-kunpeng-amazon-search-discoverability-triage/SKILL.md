# Amazon 搜索可发现性排查

## 目标

先区分“无法按 ASIN 找到”“未索引”“无可售报价”和“相关但排名靠后”，再以账户状态和查询级漏斗定位根因。

## 何时使用

- 商品已上架但前台搜不到
- 某些关键词突然没有自然或广告可见度
- 需要判断是索引、抑制、资格、库存还是排名问题

## 开始前要拿到

- 站点、ASIN/SKU、邮编、设备、登录状态、查询和采样时间
- Manage Inventory 状态、抑制/合规/类目错误、库存和报价资格
- 标题、属性、搜索词字段、父子体和最新提交/错误记录
- Search Query Performance、广告搜索词与历史可见度

缺失项必须标为 `UNKNOWN` 或 `NEEDS_EVIDENCE`；不得猜数字、补属性，或混用不同站点、主体、ASIN、币种和时间窗。

## 不可妥协的边界

- 当前法律、Amazon 官方规则、目标账户实时状态和一方业务报告优先；公开内容与第三方数据只能作为待验证启发或代理证据。
- 默认提供诊断或草案。写入前展示对象、旧值、新值、影响、停止线与回退，核对用户已有授权是否覆盖对象、动作与预算；范围已明确授权时继续执行并回读核验，只有未覆盖或扩大的范围才请求批准。
- 数值、政策、因果和执行状态分别标为 `FACT`、`ESTIMATE`、`ASSUMPTION` 或 `UNKNOWN`。
- 不保存或输出素材来源身份、账号、链接、文章编号、发布日期、阅读量、原始话术或其他可反查线索。
- AI 输出是候选，不是证据；涉及合规、税务、声明或账户风险时由合格人员复核。
- 搜索位置会因时间、位置、库存和个性化变化；一次前台搜索不是确定事实。
- 不能用“某个核心算法”解释所有不可见问题，也不能以堆词替代根因修复。
- 修复前保存版本；不得同时改标题、属性、价格和广告来掩盖原因。

## 工作流

1. 固定站点、邮编、设备和登录条件，先做精确 ASIN 与品牌/标题检索。
2. 核对在售、抑制、合规、类目、父子体、库存、报价和配送资格。
3. 区分索引缺失与已相关但自然位置靠后，记录每个测试词和时间。
4. 审计标题、关键属性、后台搜索词及最近提交错误，验证字段是否生效。
5. 用查询级曝光—点击—购买和广告数据判断需求、相关性或承接缺口。
6. 一次修复一个根因并复测；状态未清或数据不足时保持 HOLD。

## 判断状态

- `READY`：关键输入、当前规则、证据和专业复核均已满足，方案可回退。
- `HOLD`：方向可能成立，但关键事实、资格、样本或审批仍缺失。
- `STOP`：存在违法违规、证据虚假、敏感数据风险、不可承受经济性或无法回退。

## 必须交付的结果

- 可发现性故障分类
- 状态/索引/报价证据表
- 查询级漏斗诊断
- 单变量修复、复测和回退表
- 数据范围、采集时间、定义、证据状态、限制和待批准动作
