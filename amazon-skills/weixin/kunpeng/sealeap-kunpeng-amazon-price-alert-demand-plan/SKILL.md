# Amazon 目标价需求计划

## 目标

先验证目标站点的价格历史、提醒或自动购买功能，再把不同触发价的需求作为情景而非已知事实，用毛利和库存控制价格试验。

## 何时使用

- 买家端出现目标价提醒或自动购买功能
- 担心一次降价触发超出库存的需求
- 需要评估促销价、库存和利润的联动

## 开始前要拿到

- 目标站点、设备、账户与当前买家功能的实测证据
- ASIN 的真实价格历史、促销、销量、季节和竞争快照
- COGS、费用、广告、退货、最低毛利和库存覆盖
- 可获得的一方提醒/愿望清单信号；不可见则明确 UNKNOWN

缺失项必须标为 `UNKNOWN` 或 `NEEDS_EVIDENCE`；不得猜数字、补属性，或混用不同站点、主体、ASIN、币种和时间窗。

## 不可妥协的边界

- 当前法律、Amazon 官方规则、目标账户实时状态和一方业务报告优先；公开内容与第三方数据只能作为待验证启发或代理证据。
- 默认提供诊断或草案。写入前展示对象、旧值、新值、影响、停止线与回退，核对用户已有授权是否覆盖对象、动作与预算；范围已明确授权时继续执行并回读核验，只有未覆盖或扩大的范围才请求批准。
- 数值、政策、因果和执行状态分别标为 `FACT`、`ESTIMATE`、`ASSUMPTION` 或 `UNKNOWN`。
- 不保存或输出素材来源身份、账号、链接、文章编号、发布日期、阅读量、原始话术或其他可反查线索。
- AI 输出是候选，不是证据；涉及合规、税务、声明或账户风险时由合格人员复核。
- 卖家通常看不到具体买家设置的目标价；不可把提醒数量或触发价编造成已知需求。
- 降价不保证爆单，价格弹性、季节、广告和竞争均可能共同影响结果。
- 不得为制造价格历史或虚假优惠而先抬价再降价。

## 工作流

1. 实测当前站点是否提供价格历史、提醒或自动购买，并记录覆盖与日期。
2. 重建 ASIN 的标价、成交价、促销、销量、库存和外部事件时间线。
3. 把潜在目标价需求标为假设，设置悲观、基准和乐观弹性情景。
4. 计算每个价格情景的单位贡献、最大可售量、补货风险和停止线。
5. 用可回退的小幅单变量价格/促销试验验证，不同时扩大广告或更换页面。
6. 监控销量、转化、净贡献、库存和促销后回落，异常时恢复原价并复盘。

## 判断状态

- `READY`：关键输入、当前规则、证据和专业复核均已满足，方案可回退。
- `HOLD`：方向可能成立，但关键事实、资格、样本或审批仍缺失。
- `STOP`：存在违法违规、证据虚假、敏感数据风险、不可承受经济性或无法回退。

## 必须交付的结果

- 功能与可见数据边界
- 价格—需求—库存情景表
- 受控价格试验和审批表
- 触发、停止、回退与补货规则
- 数据范围、采集时间、定义、证据状态、限制和待批准动作
