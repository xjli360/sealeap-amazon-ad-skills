# Amazon 中国涉税数据核对

## 目标

按法人、店铺、报告期和币种建立平台报送数据与订单、支付、退款、费用及账簿的勾稽关系，把差异交由持证税务专业人士判断。

## 何时使用

- 收到平台涉税信息报送通知或季度报告
- 平台报送收入/费用与财务账不一致
- 需要为税务顾问准备可追溯的核对包

## 开始前要拿到

- 法律主体、税务居民地、统一标识、卖家账号和店铺映射
- 平台涉税报告、Payments、订单、退款、平台费和结算报告原件
- 会计账簿、银行收款、发票、物流/关税资料和使用的汇率规则
- 报告期、截止时间、税务机关通知及持证税务顾问意见

缺失项必须标为 `UNKNOWN` 或 `NEEDS_EVIDENCE`；不得猜数字、补属性，或混用不同站点、主体、ASIN、币种和时间窗。

## 不可妥协的边界

- 当前法律、Amazon 官方规则、目标账户实时状态和一方业务报告优先；公开内容与第三方数据只能作为待验证启发或代理证据。
- 默认提供诊断或草案。写入前展示对象、旧值、新值、影响、停止线与回退，核对用户已有授权是否覆盖对象、动作与预算；范围已明确授权时继续执行并回读核验，只有未覆盖或扩大的范围才请求批准。
- 数值、政策、因果和执行状态分别标为 `FACT`、`ESTIMATE`、`ASSUMPTION` 或 `UNKNOWN`。
- 不保存或输出素材来源身份、账号、链接、文章编号、发布日期、阅读量、原始话术或其他可反查线索。
- AI 输出是候选，不是证据；涉及合规、税务、声明或账户风险时由合格人员复核。
- 这是高风险税务流程，不构成纳税申报或法律意见；结论和提交必须由合格专业人士复核。
- 严禁通过分拆收入、变更主体、迁移店铺、隐瞒账号、伪造成本或少报收入规避报送和纳税。
- 不得在 Skill、日志或聊天中暴露完整税号、银行账号、凭证或个人身份信息。

## 工作流

1. 冻结报告原件和版本，确认适用法规、报告期、主体、平台与截止时间。
2. 建立法律主体—卖家账号—店铺—币种—结算账户映射，所有未知关系单独列出。
3. 按订单、退款、平台费、其他服务费和结算逐层勾稽平台报告与一方报表。
4. 统一收入确认、退款、税费、费用和汇率口径，保留原币与折算路径。
5. 对每个差异记录金额、来源、可能原因、支持凭证和待专业判断事项。
6. 将核对包交持证税务专业人士确认；任何申报、调整或平台反馈另行审批并留回执。

## 判断状态

- `READY`：关键输入、当前规则、证据和专业复核均已满足，方案可回退。
- `HOLD`：方向可能成立，但关键事实、资格、样本或审批仍缺失。
- `STOP`：存在违法违规、证据虚假、敏感数据风险、不可承受经济性或无法回退。

## 必须交付的结果

- 主体与账号映射表
- 平台报告—订单—支付—账簿勾稽表
- 差异、凭证和未知项清单
- 税务专业复核包与提交审批记录
- 数据范围、采集时间、定义、证据状态、限制和待批准动作
