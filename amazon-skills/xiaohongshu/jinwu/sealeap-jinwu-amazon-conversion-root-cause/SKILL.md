# Amazon 不出单的根因排查：流量、准确性与产品力

## 目标

按‘有没有流量→流量准不准→产品力够不够’的固定顺序定位不出单的根因，用细分市场基准校准转化率，并把补货与继续投入的决策建立在自然单占比与基准对照之上。

## 使用范围

- 优先处理转化诊断任务；从专项证据卡选择与当前对象和问题直接相关的主题。
- 集合名称用于维护文件归属，不限制用户要求的交叉验证。其他来源与业务域的证据须分别标注，再按同口径比较。
- 本 Skill 可独立使用，不依赖仓库中的私有语义稿。保留去标识化边界，不恢复原素材身份或逐条映射。

## 适用任务

- 不出单根因排查
- 转化率基准对照
- 补货或停止投入决策
- 点击率与 CPC 异常解释

## 开始前要拿到

- 曝光、点击、点击率、转化率、广告单与总单（同口径同窗口）
- 搜索词报告中的实际搜索词与进入路径
- 细分市场的一方或第三方转化率基准及其定义
- 评论数、评分、价格带位置与竞品对照
- 折扣测试结果（若已做）

缺少字段时明确标为 `UNKNOWN` 或 `NEEDS_EVIDENCE`，不要补造数据。

## 不可妥协的边界

- 本 Skill 来自去标识化语义转译，不保留或推断素材来源身份，也不把素材观点冒充 Amazon 当前政策。
- 产品事实、账户事实和 Amazon 一方报告优先；第三方数据必须标明 Provider、站点、日期、样本和估算口径。
- 不捏造销量、搜索量、成本、合规状态、产品属性、评论、平台通知或执行结果。
- 默认提供诊断或草案。写入前展示对象、旧值、新值、影响、停止线与回退，核对用户已有授权是否覆盖对象、动作与预算；范围已明确授权时继续执行并回读核验，只有未覆盖或扩大的范围才请求批准。
- 平台规则、费率、界面和资格会变化；执行前复核当前官方文档与后台状态。
- 转化率基准来自一方工具或第三方估算时必须注明定义与窗口。
- 价格回升困难，降价测试前写明回退路径。

## 工作流

1. 核对流量是否存在与规模，样本不足先积累。
2. 用搜索词报告判断流量准确性，不准则调整定向。
3. 流量准确仍不转化时判定产品力问题，停止用广告解决。
4. 把转化率放到细分基准里比较，注意基准的样本范围、归因窗口与流量来源。
5. 计算自然单占比，按‘有现在/有未来’四象限决定补货、维持或停止。
6. 把折扣测试当作有停止线的实验，避免无上限让利。

## 专项路由

- **三步排查**：有流量吗→准确吗→产品力够吗；前两步是广告能力，第三步不属于广告范畴。
- **两分根因**：点击率代理流量准确性，转化率代理产品力；点击正常转化低先怀疑产品。
- **基准对照**：细分基准多为优秀水平而非平均，打排名需高于基准；低价不自动带来高转化。
- **补货陷阱**：广告后台数据漂亮不等于产品健康，用自然单占比与基准对照决定补货。
- **CPC 异常**：CPC 远高于同行且无曝光，先看点击率与收录，再看流量准确性，最后判定产品问题。

## 必须交付的结果

- 排查路径与每步证据
- 转化率基准对照表
- 自然单占比与四象限决策
- 折扣或定向实验方案（含停止线）
- 继续投入、维持或停止的结论与理由

结尾列出站点、时间窗、数据口径、证据、假设、缺口、风险、下一步和所有待批准动作。证据不足时写 `HOLD`，不得包装成可直接执行。
