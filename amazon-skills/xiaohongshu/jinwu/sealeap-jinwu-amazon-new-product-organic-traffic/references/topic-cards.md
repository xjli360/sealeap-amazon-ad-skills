# Amazon 新品期与自然流量：起算、诊断与推排名：专项证据卡

本文件汇总该组内相近主题的 8 张证据卡，每张卡对应一个去标识化语义单元。以下是分析台账字段，不是可直接传给某个 API 的参数；取数前需映射到实时 schema。只加载当前问题直接相关的卡片，不要无差别执行全部内容。

## 自然单多于广告单的诊断

- 判断要求：新品自然单多于广告单是好信号，原因要么是广告投入偏少而产品自然表现强，要么是广告流量偏离而自然流量才是对的；下一步是寻找新的自然流量突破口。
- 方法要点：
  - 比较自然转化率与广告转化率：自然明显更高说明广告流量偏离，需要修正定向。
  - 若两者接近而自然流量更大，说明广告预算相对产品表现偏少，可适度增加。
  - 寻找突破：哪些关键词值得冲排名、关联流量能否再推。
  - 记录每次调整后的自然/广告单比例变化。
- 待验证与降级：
  - 归因窗口一致才可比较两类转化率。
  - 新品期数据量小，结论需持续验证。
- 最小证据字段：`asin`, `organic_orders`, `ad_orders`, `organic_cvr`, `ad_cvr`, `ad_spend`, `keyword_opportunities`, `window`。
- 输出要求：记录事实、证据来源、站点、时间窗、假设、缺口、风险、停止条件和下一步。

## 广告出单少而自然单多时的自然排名工作

- 判断要求：自然单少的根因通常是有排名的关键词太少或排名太低；解决路径是扩大有排名的关键词数量或把已有排名的词推高，而不是先调广告。
- 方法要点：
  - 统计有自然排名的关键词数量与位置分布。
  - 选择扩展目标：新增词的排名建设或核心词的位置提升。
  - 用广告与页面优化配合推动目标词，跟踪自然排名变化。
  - 把自然单、广告单与排名变化做同表复盘。
- 待验证与降级：
  - 排名数据需标注采集工具与时间。
  - 词的选择需与转化率数据结合。
- 最小证据字段：`asin`, `ranked_keyword_count`, `rank_distribution`, `target_keywords`, `organic_orders`, `ad_orders`, `window`。
- 输出要求：记录事实、证据来源、站点、时间窗、假设、缺口、风险、停止条件和下一步。

## 关键词排名的三个驱动量

- 判断要求：推动关键词排名的核心是三项：该词在对应位置的转化率相对同行的优势（对位优）、来自该词的订单量、以及产品订单量的波动系数；活动放几个词由是否需要精确控制某词的流量与单量决定。
- 方法要点：
  - 按位置（搜索结果、商品页面）分别比较转化率，确保在投放位置上优于同行。
  - 统计每个目标词带来的订单量，作为排名推动的直接输入。
  - 控制日单量波动，避免大起大落。
  - 需要精确控制的词单独成活动；不重要或流量小的词可合并。
- 待验证与降级：
  - 三项驱动是经验模型，需用自家排名与订单数据验证。
  - 对位转化率需同位置同窗口比较。
- 最小证据字段：`keyword`, `placement`, `cvr_vs_peers`, `orders_from_keyword`, `daily_units_volatility`, `campaign_keyword_count`, `rank_series`。
- 输出要求：记录事实、证据来源、站点、时间窗、假设、缺口、风险、停止条件和下一步。

## 新品期起算点

- 判断要求：新品期从商品首次进入可售状态起算固定天数；上架时带库存哪怕随后改为零也已触发起算，只有从未可售（库存为零直至正式上架或预售）才从正式开售起算。
- 方法要点：
  - 规划发布时确认首次可售的时点与后续推广计划一致。
  - 需要延后起算时，创建链接时库存置零并保持不可售直到开售。
  - 记录首次可售日期作为新品期倒计时的起点。
  - 新品期内的推广节奏据此安排。
- 待验证与降级：
  - 新品期长度与规则以平台当前说明为准。
  - 可售状态的判定以后台记录为准。
- 最小证据字段：`asin`, `first_sellable_date`, `inventory_at_creation`, `fulfillment_mode`, `launch_date`, `new_product_window_end`。
- 输出要求：记录事实、证据来源、站点、时间窗、假设、缺口、风险、停止条件和下一步。

## 新链接的盈亏预期

- 判断要求：新链接推广期不亏就是优秀，不应过早追求利润；此阶段的目标是把排名与自然流量做起来。视频广告属于品牌广告体系，主要用途是品牌推广而非新链接直接出单。
- 方法要点：
  - 为新链接设定阶段目标：先不亏，再排名，最后利润。
  - 推广期评估用自然流量与排名变化，而非当期利润。
  - 视频广告的角色定位为品牌与认知，不用其衡量新链接转化效率。
  - 达到‘不亏’后再决定是否加投做排名。
- 待验证与降级：
  - 广告产品归属与资格以当前广告后台为准。
  - 阶段目标需结合现金流承受力。
- 最小证据字段：`asin`, `stage`, `orders_14d`, `ad_spend`, `profit`, `organic_rank`, `campaign_type`。
- 输出要求：记录事实、证据来源、站点、时间窗、假设、缺口、风险、停止条件和下一步。

## 头部集中类目的新链接生存判断

- 判断要求：在流量与广告位高度集中在头部的类目里，无评论、无价格优势的新链接靠常规广告几乎必然亏损；可行路径只有合规的低价让利起量或差异化选品，任何操纵评论或订单的做法都属于不可接受的风险。
- 方法要点：
  - 先判断类目的流量集中度：头部链接占据搜索首屏和广告位的比例。
  - 对新链接做三项自检：评论基础、价格优势、差异化卖点，三项皆无时不进入该类目。
  - 若坚持进入，只保留合规路径：限时低价或优惠让利换取初始销量，并预先计算可承受的亏损上限。
  - 个人卖家优先选择头部集中度低的细分市场，而不是与头部同位竞争。
- 待验证与降级：
  - 素材中提到的刷单、控评路径违反平台政策，记为 STOP，不得转译为可执行选项。
  - 让利起量的预算上限与周期是经验值，须按现金流校准。
- 最小证据字段：`marketplace`, `category`, `top_n_traffic_share`, `review_count`, `price_vs_median`, `differentiation_note`, `loss_cap`, `window`。
- 输出要求：记录事实、证据来源、站点、时间窗、假设、缺口、风险、停止条件和下一步。

## 多变体新品的推广集中度

- 判断要求：变体多、库存少时，先看同类目竞品的流量是集中在单一子体还是分散，再决定集中推一个子体或整组投放。
- 方法要点：
  - 用第三方或前台抽样，记录竞品各子体在核心关键词下的排名与流量分布。
  - 同一父体下不同子体可在同一关键词下同时获得排名，因此整组投放并非错误，只是预算分散。
  - 预算和库存有限时，参考竞品把火力集中到一到两个主流子体，其余子体依靠变体页面承接。
  - 记录集中推广后其他子体的自然单变化，作为是否扩展的依据。
- 待验证与降级：
  - 竞品子体流量分布是第三方估算，需标注 Provider 与采样时间。
  - 变体排名规则可能随平台调整，执行前复核当前表现。
- 最小证据字段：`marketplace`, `parent_asin`, `child_asin_list`, `inventory_per_child`, `competitor_child_traffic_share`, `keyword`, `budget_daily`, `captured_at`。
- 输出要求：记录事实、证据来源、站点、时间窗、假设、缺口、风险、停止条件和下一步。

## 促销加广告推排名与价格带效应

- 判断要求：促销叠加广告推排名是常规手段，但直接降价与设置折扣不同：降价会改变产品所处价格带、竞争对手和人群标签，折扣则保留原价带。
- 方法要点：
  - 推排名前先验证价格弹性：小幅折扣后观察单量变化，弹性明显才继续。
  - 优先用促销/折扣工具而不是直接改标价，保持价格带与竞品集合不变。
  - 记录改价前后的竞品集合（同价带的对手）变化，判断是否进入了新的竞争环境。
  - 推排名期间把广告与促销的贡献分开记录，避免把促销带来的单量归因于广告。
- 待验证与降级：
  - 价格影响权重的说法是经验假设，需用自家数据验证。
  - 促销工具的类型、费用和资格以当前后台为准。
- 最小证据字段：`marketplace`, `asin`, `list_price`, `promo_type`, `promo_depth`, `orders_before`, `orders_after`, `competitor_set_before`, `competitor_set_after`, `window`。
- 输出要求：记录事实、证据来源、站点、时间窗、假设、缺口、风险、停止条件和下一步。
