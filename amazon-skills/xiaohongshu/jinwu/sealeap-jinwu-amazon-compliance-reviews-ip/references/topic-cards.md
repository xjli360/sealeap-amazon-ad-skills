# Amazon 合规边界：知识产权初筛、评论政策与竞品异常识别：专项证据卡

本文件汇总该组内相近主题的 6 张证据卡，每张卡对应一个去标识化语义单元。以下是分析台账字段，不是可直接传给某个 API 的参数；取数前需映射到实时 schema。只加载当前问题直接相关的卡片，不要无差别执行全部内容。

## 知识产权三类风险的初筛清单

- 判断要求：商标、专利、版权是最常见的三类侵权来源；文案与关键词不用他人品牌名、外观独特的产品必查专利、不复制他人图片文案与独特拍摄创意，能把风险降到可控，但任何结论都需专业复核。
- 方法要点：
  - 商标：检查标题、五点、描述、后台关键词是否含他人品牌名或图形标识；广告定向他人品牌词与文案使用不同，需分别判断。
  - 专利：对外观有独特设计的产品，上架前用专利检索工具按目标国家检索外观与实用专利；大众化外观可降低检索优先级但不免检。
  - 版权：图片、文案、影视游戏形象、独特拍摄角度均可能构成侵权，全部使用自有素材。
  - 把每个 SKU 的检索记录与结论归档，作为申诉与复核依据。
- 待验证与降级：
  - 素材中‘AI 重制图片即无侵权风险’的说法不成立，重制他人素材仍可能侵权，记为不可采用。
  - 法律结论必须由知识产权专业人士确认。
- 最小证据字段：`marketplace`, `sku`, `trademark_check_ref`, `patent_check_ref`, `copyright_asset_source`, `checked_at`, `reviewer`。
- 输出要求：记录事实、证据来源、站点、时间窗、假设、缺口、风险、停止条件和下一步。

## ‘请求评论’功能的使用条件

- 判断要求：官方请求评论功能本身可用，但主动邀请会放大两端体验的表达：只有对产品满意度有充分把握时才使用，否则更可能引来负面评价。
- 方法要点：
  - 先用退货率、客服工单和已有评分判断产品满意度是否高于类目水平。
  - 满意度不明确或偏低时不批量邀请，优先修复产品与页面预期。
  - 分批小样本邀请并观察评分变化，再决定是否扩大。
  - 尊重运营人员基于数据的谨慎判断，不以管理者直觉覆盖。
- 待验证与降级：
  - 邀请功能的规则与频次限制以当前平台政策为准。
  - 评分变化需足够样本才能归因。
- 最小证据字段：`marketplace`, `asin`, `return_rate`, `rating`, `review_request_sent`, `reviews_received`, `rating_delta`, `window`。
- 输出要求：记录事实、证据来源、站点、时间窗、假设、缺口、风险、停止条件和下一步。

## 识别竞品异常起量的证据链

- 判断要求：判断竞品是否存在人为刷量，看四条证据：自然流量得分在无广告、无促销情况下陡增；小类排名在单日跳升到需要数十单的位置；站外（搜索引擎与社媒）没有推广痕迹；关键词排名同步快速上升（说明权重被归到关键词）。
- 方法要点：
  - 用第三方流量分析工具区分自然流量得分与广告流量得分的时间序列。
  - 把小类排名跳变换算成所需日单量，与该链接的正常单量比较。
  - 用品牌名加核心词在搜索引擎与短视频平台检索站外推广痕迹。
  - 站外直链购买通常不携带关键词权重，关键词排名同步暴涨更符合按词刷单特征。
  - 只把结论用于自身策略（是否进入、如何定位），不用于指控或举报之外的用途。
- 待验证与降级：
  - 第三方流量得分是代理指标，需标注 Provider。
  - 排名与单量的换算关系随类目变化，需用当期数据。
- 最小证据字段：`competitor_asin`, `organic_score_series`, `ad_score_series`, `promo_flags`, `subcategory_rank_series`, `estimated_daily_units`, `offsite_trace`, `keyword_rank_series`。
- 输出要求：记录事实、证据来源、站点、时间窗、假设、缺口、风险、停止条件和下一步。

## 早期评论计划回评的解读

- 判断要求：官方早期评论计划回评率有限，评分结果主要反映产品质量：小样本个别差评可能是运气，大样本评分低于类目平均则是质量或设计缺陷信号。
- 方法要点：
  - 记录申请数量与回评数量，计算回评率。
  - 把回评平均分与类目平均比较，样本足够时作为质量判断。
  - 评分明显偏低时优先排查产品缺陷与页面预期差，而不是继续推广。
  - 评分与转化都达标仍不出单时，问题转向竞争力与定价。
- 待验证与降级：
  - 素材中提到的付费指定评论者等干预评分做法违反政策，记为 STOP。
  - 回评率与评分基线随类目变化。
- 最小证据字段：`asin`, `vine_enrolled_units`, `reviews_received`, `avg_rating`, `category_avg_rating`, `defect_reports`, `window`。
- 输出要求：记录事实、证据来源、站点、时间窗、假设、缺口、风险、停止条件和下一步。

## 差评后的沟通边界

- 判断要求：已退款的差评买家仍可通过官方渠道沟通，但沟通目标只能是解决问题与确认服务满意度；不得要求修改、更新或删除评论，也不得以任何方式暗示好评。
- 方法要点：
  - 通过官方买卖沟通渠道询问遇到的问题并提供解决方案。
  - 问题解决后可确认服务体验，但不提出与评论相关的请求。
  - 把每次沟通记录归档，作为合规证据。
  - 评论内容的变化只能由买家自主决定。
- 待验证与降级：
  - 素材中‘委婉请其更新评论’的做法与平台评论政策冲突，记为 STOP。
  - 沟通模板需对照当前政策复核。
- 最小证据字段：`order_id`, `review_id`, `issue_type`, `resolution`, `message_log_ref`, `policy_ref`。
- 输出要求：记录事实、证据来源、站点、时间窗、假设、缺口、风险、停止条件和下一步。

## 合并变体后评论展示上限的政策快照

- 判断要求：平台曾调整合并变体的早期评论展示规则，只保留其认为对买家最有参考价值的有限条数，且可能包含差评；依赖‘多子体各申请早期评论再合并’的做法失去确定性。
- 方法要点：
  - 把评论相关政策变化记录为快照：生效日期、影响对象、待观察项。
  - 重新评估每个子体申请早期评论的投入产出，不再假设合并后全部保留。
  - 观察既有合并链接是否被拆分、跨站点评论是否受影响，作为待验证项。
  - 以产品质量与合规获取评论为主策略。
- 待验证与降级：
  - 政策细节与时间以当前官方帮助页为准，素材内容仅为历史快照。
- 最小证据字段：`policy_ref`, `effective_date`, `affected_object`, `child_asin_count`, `reviews_displayed`, `observed_change`, `captured_at`。
- 输出要求：记录事实、证据来源、站点、时间窗、假设、缺口、风险、停止条件和下一步。
