# Amazon 目录与库存运维：表格、变体拆合、断货与购物车

## 目标

把目录与库存的日常操作建立在可恢复、可回读的流程上：表格版本化、自动化工具执行后回读、断货前调低而非关闭广告、购物车丢失按比价来源分路径申诉。

## 使用范围

- 优先处理目录与库存运维任务；从专项证据卡选择与当前对象和问题直接相关的主题。
- 集合名称用于维护文件归属，不限制用户要求的交叉验证。其他来源与业务域的证据须分别标注，再按同口径比较。
- 本 Skill 可独立使用，不依赖仓库中的私有语义稿。保留去标识化边界，不恢复原素材身份或逐条映射。

## 适用任务

- 表格发布与链接恢复
- 变体拆合操作
- 低库存期间的广告与补货协同
- 购物车丢失处置

## 开始前要拿到

- 各 SKU 的表格模板版本与提交记录
- SKU→ASIN 映射与库存状态
- 剩余库存、日均单量、补货到仓日期
- 购物车状态与系统提示的比价来源链接
- 后台 AI 助手可用性与支持的操作

缺少字段时明确标为 `UNKNOWN` 或 `NEEDS_EVIDENCE`，不要补造数据。

## 不可妥协的边界

- 本 Skill 来自去标识化语义转译，不保留或推断素材来源身份，也不把素材观点冒充 Amazon 当前政策。
- 产品事实、账户事实和 Amazon 一方报告优先；第三方数据必须标明 Provider、站点、日期、样本和估算口径。
- 不捏造销量、搜索量、成本、合规状态、产品属性、评论、平台通知或执行结果。
- 默认提供诊断或草案。写入前展示对象、旧值、新值、影响、停止线与回退，核对用户已有授权是否覆盖对象、动作与预算；范围已明确授权时继续执行并回读核验，只有未覆盖或扩大的范围才请求批准。
- 平台规则、费率、界面和资格会变化；执行前复核当前官方文档与后台状态。
- 表格模板与 AI 助手能力随站点更新，提交前复核。
- 差异举证必须基于真实产品事实。

## 工作流

1. 以表格发布并版本化，异常时用原表格恢复映射。
2. 变体拆合优先用后台 AI 助手，执行后回读变体关系与库存映射。
3. 库存告急时按可售天数调低预算，补货计划优先于任何隐藏链接类做法。
4. 购物车丢失先判定比价来源属于自家同品、他人冒用还是他人同款，分别改价、清除链接或举证差异。
5. 所有操作记录对象、旧值、新值与回读结果。

## 专项路由

- **表格恢复**：映射类问题只能靠表格解决，表格是运维资产。
- **变体拆合**：自然语言指令给后台助手，执行前确认范围，执行后回读。
- **断货与广告**：调低不关闭；断货必影响权重，唯一解是补货速度。
- **购物车丢失**：同品牌同品→改价或清除链接；他人同款→举证非同品与价格差异。
