# Amazon 广告的预算、竞价与调整节奏

## 目标

把广告调整从直觉改成有数据门槛的动作：区分预算受限与展示受限，按样本量与归因窗口决定调整频率，只在小时级或位置级数据充分且差异稳定时做分时或倍率调整，并用竞价分档测试替代重复活动。

## 使用范围

- 优先处理广告预算、竞价与调整节奏任务；从专项证据卡选择与当前对象和问题直接相关的主题。
- 集合名称用于维护文件归属，不限制用户要求的交叉验证。其他来源与业务域的证据须分别标注，再按同口径比较。
- 本 Skill 可独立使用，不依赖仓库中的私有语义稿。保留去标识化边界，不恢复原素材身份或逐条映射。

## 适用任务

- 有效广告的放量方式
- 调整频率与观察窗口设定
- 分时调价与广告位倍率的可行性判断
- 自动广告结构设计
- 广告依赖度测试

## 开始前要拿到

- 活动级预算、预算耗尽时点、竞价与建议竞价
- 按位置与按小时拆分的曝光、点击、转化、CPC、ACOS（若可得）
- 归因窗口与产品客单价
- 产品类型、库存规模与日预算上限
- 自然单与广告单时间序列

缺少字段时明确标为 `UNKNOWN` 或 `NEEDS_EVIDENCE`，不要补造数据。

## 不可妥协的边界

- 本 Skill 来自去标识化语义转译，不保留或推断素材来源身份，也不把素材观点冒充 Amazon 当前政策。
- 产品事实、账户事实和 Amazon 一方报告优先；第三方数据必须标明 Provider、站点、日期、样本和估算口径。
- 不捏造销量、搜索量、成本、合规状态、产品属性、评论、平台通知或执行结果。
- 默认提供诊断或草案。写入前展示对象、旧值、新值、影响、停止线与回退，核对用户已有授权是否覆盖对象、动作与预算；范围已明确授权时继续执行并回读核验，只有未覆盖或扩大的范围才请求批准。
- 平台规则、费率、界面和资格会变化；执行前复核当前官方文档与后台状态。
- 竞价倍数、预算档位与观察天数均为经验起点。
- 每次只改一个主要变量并记录回退值。

## 工作流

1. 先填齐前置条件：产品类型、库存、预算上限，缺项标 NEEDS_EVIDENCE。
2. 判断限制来源：预算提前耗尽加预算，预算未耗尽却不放量则提竞价。
3. 按日点击量与归因窗口估算最短调整间隔，高客单价延长。
4. 分时或倍率调整只在小时级或位置级数据充分且差异稳定时执行，保留对照期。
5. 自动广告按低中高竞价分档测试，淘汰重复设置。
6. 对不出单的广告做分步降预算的依赖度测试，观察自然单。

## 专项路由

- **放量方式**：预算耗尽→加预算；预算未耗尽→适度加竞价。
- **调整频率**：由数据充分性决定：曝光点击实时，订单受归因窗口滞后。
- **分时与倍率**：没有小时级或位置级数据就不做；低出单时段可能因 CPC 低而 ACOS 最优。
- **自动广告分档**：多个自动广告只有在竞价分档时才有意义。
- **新品广告位与标签**：新品拿不到搜索结果广告位是常态，短期高竞价换展示后回落；标签是结果不是目标。
- **依赖度测试**：广告只放大有竞争力的产品；分步降预算看自然单是否受影响。
