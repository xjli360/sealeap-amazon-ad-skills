# Amazon 广告的预算、竞价与调整节奏：专项证据卡

本文件汇总该组内相近主题的 8 张证据卡，每张卡对应一个去标识化语义单元。以下是分析台账字段，不是可直接传给某个 API 的参数；取数前需映射到实时 schema。只加载当前问题直接相关的卡片，不要无差别执行全部内容。

## 放大有效广告：加预算还是加竞价

- 判断要求：广告表现好且每日提前耗尽预算时先加预算；预算未耗尽却想放量时，加预算无效，需要适当提高竞价获取更多展示。
- 方法要点：
  - 检查预算耗尽时点：若持续在当日中途耗尽，先加预算并观察单量与 ACOS。
  - 若预算全天可用仍未放量，说明受限的是展示机会，逐步提高竞价并记录每次变化。
  - 每次只改一个变量，保留基线窗口。
  - 在不理解一项设置的作用前不投放，先小预算学习再放量。
- 待验证与降级：
  - 加价幅度与观察窗口是经验值，需按类目竞争校准。
  - 预算耗尽时点需用小时级或日报数据确认。
- 最小证据字段：`campaign`, `budget_daily`, `budget_exhaust_time`, `bid`, `impressions`, `orders`, `acos`, `change_log`, `window`。
- 输出要求：记录事实、证据来源、站点、时间窗、假设、缺口、风险、停止条件和下一步。

## 广告打法的前置条件

- 判断要求：‘某类产品广告怎么打’没有通用答案：打法由产品类型（标品偏精准、非标偏泛流量）、库存规模和预算规模共同决定，同一产品在不同库存与预算下打法完全不同。
- 方法要点：
  - 提问或决策前先填齐三项：产品类型与流量结构、可售库存与补货计划、日预算上限与可承受亏损。
  - 按库存决定推进节奏：大库存可承受高预算快速拉升，小库存必须控制消耗避免断货。
  - 按预算决定结构复杂度：小预算集中少量活动与词，大预算分层测试。
  - 把这些前置条件写进广告方案模板，缺项时标 NEEDS_EVIDENCE。
- 待验证与降级：
  - 标品精准、非标泛流量是倾向，需用数据验证。
  - 预算档位是经验值。
- 最小证据字段：`asin`, `product_type`, `inventory_units`, `inbound_plan`, `budget_daily`, `loss_cap`, `campaign_structure`。
- 输出要求：记录事实、证据来源、站点、时间窗、假设、缺口、风险、停止条件和下一步。

## 广告调整频率的判据

- 判断要求：调整频率不应由‘怕影响权重’或‘怕虚度光阴’决定，而由数据充分性决定：曝光与点击近实时，订单受归因窗口影响会滞后（高客单价滞后更长）；投入大、短窗口内数据量足够时高频调整合理，数据不足时频繁调整没有依据。
- 方法要点：
  - 区分实时指标（曝光、点击）与滞后指标（归因订单），为订单类判断留出归因窗口。
  - 按日预算与点击量估算达到统计可读所需的最短窗口，作为最小调整间隔。
  - 高客单价产品延长观察窗口。
  - 每次调整写明数据依据，没有依据就不动。
- 待验证与降级：
  - 归因窗口长度以当前广告产品说明为准。
  - ‘当天订单接近最终订单’只对低客单价快速决策品类成立。
- 最小证据字段：`campaign`, `budget_daily`, `clicks_per_day`, `attribution_window`, `price_point`, `min_review_interval`, `change_log`。
- 输出要求：记录事实、证据来源、站点、时间窗、假设、缺口、风险、停止条件和下一步。

## 广告位倍率调整的数据充分性

- 判断要求：同一产品在不同广告位（搜索顶部、搜索其余、商品页面）的相对表现无法预判，且会随时间波动；只有点击样本足够大且位置间差异稳定时，才把倍率向优势位置倾斜，样本不足或差异不稳定时不动倍率。
- 方法要点：
  - 按位置拉出全生命周期与近期两个窗口的点击、转化、ACOS，比较结论是否一致。
  - 设定最小点击样本门槛，短窗口中任一位置点击过少时不据此调整。
  - 差异稳定且预算与人力允许时，按位置表现动态调整倍率；小预算账户保持简单结构。
  - 同一产品的不同广告形式可能有完全相反的位置偏好，分别评估。
- 待验证与降级：
  - ‘卡广告位’类经验说法只作假设，以自家测试数据为准。
  - 位置表现随季节与竞争变化，定期复核。
- 最小证据字段：`campaign`, `placement`, `clicks`, `orders`, `acos`, `window_short`, `window_lifetime`, `modifier`, `min_sample`, `decision`。
- 输出要求：记录事实、证据来源、站点、时间窗、假设、缺口、风险、停止条件和下一步。

## 多个自动广告的用途

- 判断要求：开多个自动广告只有在设置不同（如低、中、高三档竞价）时才有意义，目的是测试不同竞价下的表现；完全相同设置的多个自动广告没有价值。
- 方法要点：
  - 按建议竞价的低、中、高三档分别建活动。
  - 其余设置保持一致，只让竞价成为变量。
  - 比较三档的曝光、点击、转化与 ACOS，选出效率最高的档位。
  - 淘汰重复设置的活动。
- 待验证与降级：
  - 三档的具体倍数是经验做法。
  - 测试需足够样本与时间。
- 最小证据字段：`campaign`, `bid_tier`, `bid`, `impressions`, `clicks`, `orders`, `acos`, `window`。
- 输出要求：记录事实、证据来源、站点、时间窗、假设、缺口、风险、停止条件和下一步。

## 分时调价的数据前提

- 判断要求：按‘容易出单时段加预算加竞价、不易出单时段减’的直觉做分时调价没有依据；决策需要按小时拆分的历史广告数据（曝光、点击、点击率、转化率、CPC、投产比），因为低出单时段可能因竞争少而 CPC 极低、反而是 ACOS 最优时段。
- 方法要点：
  - 先获取过去一到两个月按小时拆分的广告指标。
  - 对每个时段同时看转化率与 CPC，计算时段级 ACOS，而不是只看订单数。
  - 只有时段差异稳定且显著时才设置分时策略，并保留对照期。
  - 没有小时级数据时不做分时调整。
- 待验证与降级：
  - ‘深夜时段 CPC 更低’是常见观察，需用自家数据确认。
  - 分时功能与数据可得性以当前广告后台为准。
- 最小证据字段：`campaign`, `hour_bucket`, `impressions`, `clicks`, `ctr`, `cvr`, `cpc`, `acos_by_hour`, `window`, `control_period`。
- 输出要求：记录事实、证据来源、站点、时间窗、假设、缺口、风险、停止条件和下一步。

## 新品拿不到搜索结果广告位与标签的认识

- 判断要求：新品初期即使出价高于建议也拿不到搜索结果页广告位是常态，因为平台尚无表现数据；短期可用显著提高竞价换取首屏展示后再回落。词级荣誉标签来自在该词下表现超越同行，本身对转化几乎没有可感知帮助，不应作为目标。
- 方法要点：
  - 确认新品是否处于无表现数据阶段，把广告位缺失记为预期现象。
  - 若必须快速获得搜索结果页展示，短期把竞价提高到出现展示后逐步回落，全程记录成本。
  - 把标签视为结果而非目标：在目标词下持续提升转化与订单即可。
  - 对培训类宣传中的‘拿标秘诀’保持怀疑，用自家数据检验其价值。
- 待验证与降级：
  - 竞价倍数是经验做法，需设预算上限。
  - 标签规则与展示逻辑以平台当前说明为准。
- 最小证据字段：`asin`, `keyword`, `bid`, `suggested_bid`, `top_of_search_impression_share`, `orders`, `badge_status`, `window`。
- 输出要求：记录事实、证据来源、站点、时间窗、假设、缺口、风险、停止条件和下一步。

## 广告依赖度测试

- 判断要求：广告只能放大已有竞争力的产品，不能替代产品力；广告不出单而自然单稳定时，用分步降预算观察自然单是否受影响，未受影响即可逐步收缩至关闭。
- 方法要点：
  - 记录基线：广告单、自然单、总单量、排名。
  - 分阶段下调广告预算，每阶段观察自然单与排名变化。
  - 自然单不受影响则继续收缩；出现下滑则回退到上一档并记录依赖度。
  - 把‘靠广告提高销售’设为条件命题：只有产品数据（转化、评分）过关时才成立。
- 待验证与降级：
  - 观察窗口需覆盖至少一个完整周期，避免周内波动误判。
  - 自然单与广告单的归因窗口须一致。
- 最小证据字段：`campaign`, `budget_daily`, `ad_orders`, `organic_orders`, `organic_rank`, `step`, `window`。
- 输出要求：记录事实、证据来源、站点、时间窗、假设、缺口、风险、停止条件和下一步。
