# Amazon 筛选型经营模式：起步路径、投入纪律与生命周期

## 目标

根据资金、供应链与团队条件选定经营模式，并把筛选型经营拆成可执行的纪律：多品少量试错、统一淘汰标准、单品投入上限、生命周期预期与模式升级触发条件。

## 使用范围

- 优先处理跨境经营模式任务；从专项证据卡选择与当前对象和问题直接相关的主题。
- 集合名称用于维护文件归属，不限制用户要求的交叉验证。其他来源与业务域的证据须分别标注，再按同口径比较。
- 本 Skill 可独立使用，不依赖仓库中的私有语义稿。保留去标识化边界，不恢复原素材身份或逐条映射。

## 适用任务

- 经营模式诊断与选择
- 筛选型起步方案（首批数量、上新节奏、淘汰标准）
- 自发货与 FBA 路径的风险比较
- 模式与资源配置的一致性检查

## 开始前要拿到

- 可用资金、可承受的单次试错亏损与现金周转要求
- 供应链条件：工厂配合度、起订量、是否需要开模
- 团队产能：每日可完成的选品与上新数量
- 目标品类的热度、公模程度与货源透明度
- 现有店铺数量、SKU 数量与历史表现

缺少字段时明确标为 `UNKNOWN` 或 `NEEDS_EVIDENCE`，不要补造数据。

## 不可妥协的边界

- 本 Skill 来自去标识化语义转译，不保留或推断素材来源身份，也不把素材观点冒充 Amazon 当前政策。
- 产品事实、账户事实和 Amazon 一方报告优先；第三方数据必须标明 Provider、站点、日期、样本和估算口径。
- 不捏造销量、搜索量、成本、合规状态、产品属性、评论、平台通知或执行结果。
- 默认提供诊断或草案。写入前展示对象、旧值、新值、影响、停止线与回退，核对用户已有授权是否覆盖对象、动作与预算；范围已明确授权时继续执行并回读核验，只有未覆盖或扩大的范围才请求批准。
- 平台规则、费率、界面和资格会变化；执行前复核当前官方文档与后台状态。
- 素材中的备货数量、预算档位与月销区间只说明方法，不作为默认值。
- 任何涉及评论操纵的‘模式配置’一律记为 STOP。

## 工作流

1. 写清当前模式假设（铺货、筛选型精铺、精品）并核对资源是否匹配。
2. 设定单品投入上限、首批数量档与观察期，形成淘汰与补货规则。
3. 评估起步路径：小批量 FBA 直接试错，或自发货测品再转仓，标注各自的效率与被复制风险。
4. 按热度、公模程度与货源透明度预估候选品生命周期，选择热门快进快出、极冷门或非公模三条路径之一。
5. 把‘只筛选不培养’落成流程：达不到标准即淘汰，复盘对象是选品方法而非单品。
6. 设定模式升级的条件触发（资金、数据、团队），而非时间触发。

## 专项路由

- **模式选择与平台选择**：以‘大量被验证盈利的卖家’评估平台，以资金与能力评估模式；不具备精品条件时不强做精品。
- **起步路径**：小批量 FBA 试错与自发货测品各有风险：前者控制单次亏损，后者效率低且易被 FBA 卖家截胡。
- **上新节奏与筛选闭环**：自发货铺货靠日上新量，垂直快上新靠开发→小批测试→SOP 数据筛选的循环。
- **投入纪律**：单品投入占总资金的小比例；模式与首批数量、广告预算、素材、文案、店铺规模一致。
- **生命周期**：越火的公模品越短命；可行路径是热门快进快出、极冷门或非公模难搜货源。
