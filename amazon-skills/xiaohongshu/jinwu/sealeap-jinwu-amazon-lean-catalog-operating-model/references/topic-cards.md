# Amazon 筛选型经营模式：起步路径、投入纪律与生命周期：专项证据卡

本文件汇总该组内相近主题的 10 张证据卡，每张卡对应一个去标识化语义单元。以下是分析台账字段，不是可直接传给某个 API 的参数；取数前需映射到实时 schema。只加载当前问题直接相关的卡片，不要无差别执行全部内容。

## 自发货铺货模式的最低上新速率

- 判断要求：自发货铺货依赖数量，日上新量是该模式的硬约束；上新前用图片和文本做侵权初筛，把速率与合规同时纳入流程。
- 方法要点：
  - 把每日‘选 N 个、上 N 个’设为可量化的动作目标，连续执行数周后再评估日单量，而不是凭少数 SKU 判断模式可行性。
  - 把速率目标与团队产能对照：若个人无法维持行业常见上新量，模式本身不适合，而非选品问题。
  - 上新前用商标与专利检索工具，按目标国家逐一检索图片与关键词，形成检索记录；检索不能保证零风险，但能显著降低概率。
  - 把上新数、出单数、被投诉数按周记录，观察漏斗。
- 待验证与降级：
  - ‘每日上新多少个’和‘几个月破多少单’都是经验目标，只作为假设。
  - 侵权初筛工具的覆盖范围有限，法律结论须专业人士确认。
- 最小证据字段：`marketplace`, `fulfillment_mode`, `daily_new_listing_target`, `daily_new_listing_actual`, `ip_screen_ref`, `orders_daily`, `complaints`, `week`。
- 输出要求：记录事实、证据来源、站点、时间窗、假设、缺口、风险、停止条件和下一步。

## 垂直快上新的筛选式经营模型

- 判断要求：单一类目内持续开发新款、小批量发货测试、按推广 SOP 跑出数据后筛选留强淘弱，是筛选型经营的最小闭环；它依赖工厂配合与自有推广 SOP，而不是单品爆款运营。
- 方法要点：
  - 把经营拆为三步循环：开发新款→小批量 FBA 测试（少量、主流规格）→按统一推广 SOP 采集数据。
  - 用一致的数据口径筛选：达到预设表现的补货与加推，未达到的停止补货并清出。
  - 把工厂开发配合度和自身开发能力作为前置条件评估，缺任一项该模式不成立。
  - 把推广 SOP 写成可复用文档，使不同款式的数据可比较。
- 待验证与降级：
  - 首批数量与测试周期是经验值，须按类目退货率与资金周转调整。
  - 该模型对时尚类等高上新品类更适用，标品未必成立。
- 最小证据字段：`category`, `new_styles_per_month`, `test_qty_per_style`, `test_window`, `sop_version`, `keep_threshold`, `kill_threshold`, `cash_cycle_days`。
- 输出要求：记录事实、证据来源、站点、时间窗、假设、缺口、风险、停止条件和下一步。

## 小批量 FBA 起步与商标跨类目使用

- 判断要求：新卖家不必从自发货起步，小批量、低成本试错的 FBA 同样可控；一个商标不限制经营类目，品牌功能、权限与防跟卖（如透明计划）可跨类目使用。
- 方法要点：
  - 起步时把风险控制在单次试错成本上：小批量首批、快速读数、快速调整。
  - 评估商标注册的三个目的：使用品牌工具、获得更高账户权限、防跟卖；据此决定注册时点而非等待选品确定。
  - 商标注册类别只影响法律保护范围，不阻止在其他类目销售；跨类目产品用品牌保护计划补足防跟卖能力。
  - 把未注册类目的法律风险单独记录，必要时补充注册。
- 待验证与降级：
  - 品牌注册资格、透明计划规则和权限以当前平台品牌相关文档为准。
  - 跨类目使用商标的法律保护范围须由商标专业人士确认。
- 最小证据字段：`marketplace`, `trademark_ref`, `registered_classes`, `selling_categories`, `brand_registry_status`, `transparency_enrolled`, `first_batch_qty`。
- 输出要求：记录事实、证据来源、站点、时间窗、假设、缺口、风险、停止条件和下一步。

## 经营模式与资源投入的一致性

- 判断要求：铺货、筛选型精铺、精品打爆是不同的经营模式，首批货量、广告预算、素材投入、文案本地化和店铺数量必须与模式匹配；用精品的投入做铺货或用铺货的投入做精品都会失衡。
- 方法要点：
  - 先明确自身模式，再对照该模式下的典型资源配置：首批数量档、日广告预算档、素材成本档、文案方式、店铺与 SKU 规模。
  - 检查是否存在错配：例如少量试销却申请大量评论计划或高成本本地化文案；大批量备货却只用最低成本素材。
  - 模式切换时同步调整全部资源项，而不是只改其中一项。
  - 把模式与资源配置写进 SOP，作为新品立项检查项。
- 待验证与降级：
  - 素材中的数量档与金额档是经验快照，不作为默认值。
  - 素材中涉及的评论操纵做法违反政策，记为 STOP。
- 最小证据字段：`business_model`, `first_batch_qty`, `ad_budget_daily`, `creative_cost`, `copy_localization`, `store_count`, `sku_count`, `review_program_qty`。
- 输出要求：记录事实、证据来源、站点、时间窗、假设、缺口、风险、停止条件和下一步。

## ‘先自发货测品再转 FBA’的结构性风险

- 判断要求：用自发货测出好品再转 FBA 看似低风险，但存在两个结构问题：个人效率远低于系统化铺货公司；测出的好品会被持续监控自发货店铺的 FBA 卖家抢先跟进，测品者沦为他人的选品探针。
- 方法要点：
  - 评估自身效率：与系统化团队的上新与筛选效率比较，判断时间价值。
  - 评估竞争暴露：自发货店铺的出单表现对外可见，做 FBA 的对手会更快复制。
  - 若仍采用此路径，缩短从测出到转 FBA 的周期，并准备 FBA 运营能力而非只会上传。
  - 把该路径列为可选但不推荐，与其他路径（小批量 FBA 直接试错）比较。
- 待验证与降级：
  - 效率差倍数是经验判断。
  - 地区性案例不构成普遍结论。
- 最小证据字段：`listing_count`, `weekly_new_listings`, `hit_rate`, `days_to_fba_switch`, `competitor_copy_lag`, `fba_capability_score`。
- 输出要求：记录事实、证据来源、站点、时间窗、假设、缺口、风险、停止条件和下一步。

## 筛选型产品的生命周期与三条存活路径

- 判断要求：热门公模产品生命周期可能只有一两个月，越火越快被卷价格；筛选型经营只有三条可行路径：热门品第一时间进入并在窗口内退出、极冷门品（月销个位数到几十单、极少被盯上）、非公模且难以网上搜到货源的产品（木、铁、树枝等无需开模的材质）。
- 方法要点：
  - 按热度估算生命周期，热门品以‘一个月内变现退出’为计划。
  - 冷门品接受低月销量，备货只覆盖实际售速。
  - 优先找无需开模、货源不透明的材质品类，靠改款抬高复制门槛。
  - 避免稍有热度的公模品，其结局大多是价格战。
- 待验证与降级：
  - 月销区间是经验分层，按类目调整。
  - 货源透明度需实际检索验证。
- 最小证据字段：`sku`, `popularity_tier`, `mold_type`, `sourcing_visibility`, `expected_lifecycle_days`, `monthly_units`, `inventory_plan`。
- 输出要求：记录事实、证据来源、站点、时间窗、假设、缺口、风险、停止条件和下一步。

## 只筛选不培养

- 判断要求：筛选型经营的核心态度是对产品‘足够不留恋’：表现不达标就换下一个，把精力投入选品方法的改进而不是研究如何把弱产品运营起来；纠结单个产品成败说明已偏离该模式。
- 方法要点：
  - 为每个产品设定统一的淘汰标准与观察期。
  - 达不到标准直接淘汰，不进入个案抢救。
  - 把复盘对象从‘这个产品怎么救’改为‘选品方法哪里错了’。
  - 定期检查团队是否在少数产品上投入了不成比例的精力。
- 待验证与降级：
  - 淘汰标准需与资金周转、类目周期匹配。
  - 该态度只适用于筛选型模式，精品模式相反。
- 最小证据字段：`sku`, `observation_window`, `kill_threshold`, `time_spent`, `decision`, `selection_method_review`。
- 输出要求：记录事实、证据来源、站点、时间窗、假设、缺口、风险、停止条件和下一步。

## 无人指导新手的试错原则

- 判断要求：没有人带的新手首批选品失败率极高，因此必须低成本试错、小步快跑、快速反应与调整；一开始就大批量备货再靠广告硬推是新手最惨烈的失败方式，备货规模只改变失败的代价而不改变结果。
- 方法要点：
  - 把首批备货限定在可承受的试错成本内。
  - 把每次失败当作经验积累，控制单次损失。
  - 缩短从发现问题到调整的周期。
  - 避免把失败归因于‘广告能力’，先归因于选品与流程。
- 待验证与降级：
  - 失败率描述是经验判断。
  - 试错规模按资金与品类调整。
- 最小证据字段：`sku`, `first_batch_qty`, `trial_cost`, `review_cycle_days`, `outcome`, `lesson`。
- 输出要求：记录事实、证据来源、站点、时间窗、假设、缺口、风险、停止条件和下一步。

## 新手的平台与模式选择

- 判断要求：平台选择以‘大量卖家被验证能盈利’为标准，主流货架平台的运营逻辑最具代表性且可迁移；平台确定后最重要的是选对经营模式而不是站点或品牌：低成本个人卖家最适合筛选型 FBA 精铺（每品少量、多品并行），条件成熟后再转向精品。
- 方法要点：
  - 用‘是否有大量可验证的盈利卖家’而非‘是否是新蓝海’评估平台。
  - 评估自身是否具备精品模式的资金、供应链与推广条件，不具备则不强行做精品。
  - 以多品少量的筛选型模式起步，把总备货分散到多个 SKU。
  - 把模式升级设为条件触发（资金、数据、团队），而不是时间触发。
- 待验证与降级：
  - 平台适合度的判断是经验观点，需结合自身资源。
  - 任何培训承诺不作为决策依据。
- 最小证据字段：`platform`, `verified_profit_evidence`, `business_model`, `capital`, `supply_chain`, `sku_count`, `units_per_sku`, `upgrade_trigger`。
- 输出要求：记录事实、证据来源、站点、时间窗、假设、缺口、风险、停止条件和下一步。

## 筛选型经营的单品投入上限

- 判断要求：筛选型铺货的选品方向是偏门蓝海，核心纪律是把单个产品的投入控制在总资金的小比例内，否则铺不开数量；精品模式相反，该投的必须投。筛选型偶尔跑出爆款是运气而非设计，不以此为目标。
- 方法要点：
  - 按总资金设定单品投入上限（货款、广告、素材合计）。
  - 超出上限的候选品直接放弃，不因看好而例外。
  - 把资金分散到足够多的偏门候选上，用数量换命中。
  - 明确当前模式，避免用精品的投入逻辑做筛选型产品。
- 待验证与降级：
  - 单品投入比例是经验纪律，按资金规模调整。
- 最小证据字段：`capital_total`, `per_sku_cap`, `sku_pipeline`, `niche_level`, `sku_spend`, `decision`。
- 输出要求：记录事实、证据来源、站点、时间窗、假设、缺口、风险、停止条件和下一步。
