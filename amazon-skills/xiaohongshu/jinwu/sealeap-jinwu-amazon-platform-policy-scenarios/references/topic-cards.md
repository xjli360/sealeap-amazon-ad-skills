# Amazon 之外的渠道与政策情景：第二平台、关税、新站点与内容平台：专项证据卡

本文件汇总该组内相近主题的 8 张证据卡，每张卡对应一个去标识化语义单元。以下是分析台账字段，不是可直接传给某个 API 的参数；取数前需映射到实时 schema。只加载当前问题直接相关的卡片，不要无差别执行全部内容。

## 第二平台的进入判断

- 判断要求：把新平台当作与主站并行的渠道选项评估，而不是替代方案；用体量、用户粘性、卖家密度、规则稳定性和首单难度五个维度打分，全部标为卖家体感或第三方估算。
- 方法要点：
  - 先列出五个维度：平台体量（对比主站某个成熟站点）、平台自带信任度、同类目中国卖家占比、规则变动频率、同等选品精力下的首单容易度。
  - 每个维度只填可核验的证据（官方公告、类目前台抽样、自家测试数据），体感判断单独标注。
  - 以主站已验证的选品与运营流程为基线，评估迁移到新平台的边际成本，而不是从零学一套打法。
  - 新平台早期常见‘搬运即出单’窗口会随规则收紧消失，把窗口期收益标为一次性而非可持续。
- 待验证与降级：
  - 平台体量与 GMV 比较是体感估算，公开文件不得写成事实。
  - 首单容易度只对同一团队、同一选品方法成立，不能跨团队迁移。
  - 入驻门槛、类目权限和费用以平台当前官方规则为准。
- 最小证据字段：`platform`, `category`, `seller_mix_sample`, `policy_change_log`, `test_sku_count`, `first_order_days`, `captured_at`。
- 输出要求：记录事实、证据来源、站点、时间窗、假设、缺口、风险、停止条件和下一步。

## 关税与小包免税政策变化的情景推演

- 判断要求：关税变化对不同履约模式的影响差异巨大：按申报价值计税的整柜/海外仓卖家受影响有限，直邮小包与依赖小包的全托管、独立站受影响最大；据此推演需求向 FBA/海外仓迁移的可能性。
- 方法要点：
  - 按履约模式列出成本结构，标出关税占售价的比例，评估涨幅对毛利的影响。
  - 识别需求迁移方向：小包模式受阻后，同品类消费可能回流到履约成熟的平台，与之重叠的品类可能出现短期增长。
  - 涨价通常滞后于成本上升，把‘同行何时涨价’作为观察指标，而不是假设立即传导。
  - 把多站点、多平台作为分散单一市场政策风险的长期选项，记录各站点的准备状态。
- 待验证与降级：
  - 具体税率、起征额与执行日期是历史快照，必须以当前海关与平台公告为准。
  - 需求迁移是假设，需用自家类目的搜索与销量数据验证。
- 最小证据字段：`marketplace`, `fulfillment_mode`, `declared_value`, `duty_rate`, `duty_share_of_price`, `competitor_price_change`, `policy_ref`, `captured_at`。
- 输出要求：记录事实、证据来源、站点、时间窗、假设、缺口、风险、停止条件和下一步。

## 关税上调与小包免税取消的应对顺序

- 判断要求：取消低值包裹免税主要冲击直邮自发货、全托管与独立站直邮，整柜进仓的 FBA/海外仓卖家受影响较小；应对顺序是先暂停高风险小包业务观望，再等物流方案调整，同时不因担心而中断必要补货。
- 方法要点：
  - 按业务线标注受影响程度：直邮小包高、海外仓中、FBA 低。
  - 估算物流成本与价格优势的变化区间，标为估算。
  - 小包业务先暂停接单观望，等待物流商推出新方案后再选择。
  - 海外仓与 FBA 有断货风险时照常补货，并持续比较物流方案。
  - 把政策变动视为全体卖家共同成本，避免个体过度焦虑导致错误决策。
- 待验证与降级：
  - 税率、起征额、执行时间与成本变化比例均为历史快照。
  - 物流成本变化需用报价单核实。
- 最小证据字段：`business_line`, `fulfillment_mode`, `duty_rate`, `de_minimis_status`, `logistics_quote_before`, `logistics_quote_after`, `stockout_risk`, `captured_at`。
- 输出要求：记录事实、证据来源、站点、时间窗、假设、缺口、风险、停止条件和下一步。

## 新兴站点与企业购的机会评估

- 判断要求：‘入局已晚’只对成熟站点成立；卖家面对的是多个开放站点，新兴站点与新开放的企业购业务竞争更少。评估一个站点看人口、人均收入、互联网与电商渗透率、平台在当地的流量地位，以及企业买家的订单量大、退货少、复购高等结构特征；开通企业购需完成当地税务声明等前置设置。
- 方法要点：
  - 用公开宏观数据（人口、人均 GDP、互联网与电商渗透率）与平台当地流量地位给站点打分。
  - 识别企业购目标行业（教育、医疗、政府、建筑、专业服务、酒店等）并据此选品。
  - 核对企业购前置条件：当地商业号码或供应商声明表等税务信息，避免买家被预扣税影响成交。
  - 把新站点作为增量实验，用独立预算与目标衡量。
- 待验证与降级：
  - 宏观数字与平台声明为历史快照，需复核当前数据。
  - 税务设置路径与表格以当前后台与税务专业意见为准。
- 最小证据字段：`marketplace`, `population`, `gdp_per_capita`, `ecommerce_penetration`, `platform_traffic_rank`, `b2b_target_sectors`, `tax_setup_status`, `captured_at`。
- 输出要求：记录事实、证据来源、站点、时间窗、假设、缺口、风险、停止条件和下一步。

## 货架平台与内容平台的备货逻辑差异

- 判断要求：货架平台流量持续稳定但爆发弱，靠广告推广，可少备多备、风险低；短视频内容平台爆发强但稳定性差，靠达人建联与素材爆量，寄样起步量大、必须备大货且无法测品，视频过热后补货无效，因此多平台卖家才有分摊风险的能力。
- 方法要点：
  - 按平台流量特性区分推广手段与备货策略。
  - 内容平台的寄样成本视为固定投入，备货量必须覆盖寄样后可能出现的爆发。
  - 评估自身是否有多平台库存共享能力来分摊内容平台的备货风险。
  - 单一内容平台起步时把‘视频火后无法补货’列为主要风险。
- 待验证与降级：
  - 寄样数量与起步量是经验值。
  - 平台流量特性随算法调整变化。
- 最小证据字段：`platform`, `traffic_pattern`, `promotion_method`, `sample_units`, `inventory_units`, `burst_capacity`, `cross_platform_inventory`。
- 输出要求：记录事实、证据来源、站点、时间窗、假设、缺口、风险、停止条件和下一步。

## 低竞争平台的选品门槛与合规底线

- 判断要求：竞争越激烈的市场对产品稀缺性与优势的要求越高，小站点与低竞争平台选品门槛更低；但任何平台都同样执行知识产权保护，仿牌与假货会导致封店与法律禁令，没有‘法外之地’。
- 方法要点：
  - 按平台竞争强度调整选品标准，低竞争平台可放宽稀缺性要求。
  - 知识产权红线不随平台变化，仿牌一律否决。
  - 把平台规则与执法案例纳入选品检查。
- 待验证与降级：
  - 竞争强度的判断为经验观察。
- 最小证据字段：`platform`, `competition_level`, `selection_bar`, `ip_risk`, `decision`。
- 输出要求：记录事实、证据来源、站点、时间窗、假设、缺口、风险、停止条件和下一步。

## 小体量平台的选品差异与小资金进入

- 判断要求：体量更小的平台上，主站可行的冷门产品可能没有市场，选品需要重新验证需求规模；新手小资金进入主站仍然可行，路径是高利润、偏门、冷门的产品而非大盘品类；任何分时段的广告判断都要先给出分时段数据。
- 方法要点：
  - 跨平台复用选品时重新估算目标平台的需求规模。
  - 小资金起步聚焦高利润偏门产品，控制铺开速度。
  - 遇到‘白天差晚上好’类判断时先要求分时段 ACOS 与转化率数据。
- 待验证与降级：
  - 平台体量对比为体感估算。
- 最小证据字段：`platform`, `demand_estimate`, `margin`, `niche_level`, `capital`, `hourly_metrics_available`。
- 输出要求：记录事实、证据来源、站点、时间窗、假设、缺口、风险、停止条件和下一步。

## 站内广告触顶后的流量来源切换

- 判断要求：当广告调整不再带来单量变化时，站内流量已接近上限，增量只能来自站外（如短视频平台），并可利用多平台之间的流量溢出。
- 方法要点：
  - 确认触顶：多轮竞价、预算、位置调整后曝光与单量均无变化。
  - 把站外流量作为独立实验：内容、达人或投放，用专属链接与折扣码衡量。
  - 多平台经营时观察溢出效应：一个平台的内容流量可能带动另一个平台的订单。
  - 站外投入与站内增量分开记账。
- 待验证与降级：
  - 站外归因需专属追踪方式，否则只能记为估算。
  - 溢出效应是观察到的案例现象，不保证复现。
- 最小证据字段：`asin`, `ad_plateau_evidence`, `offsite_channel`, `tracking_ref`, `offsite_spend`, `incremental_orders`, `window`。
- 输出要求：记录事实、证据来源、站点、时间窗、假设、缺口、风险、停止条件和下一步。
