# Amazon 之外的渠道与政策情景：第二平台、关税、新站点与内容平台

## 目标

把平台与政策变化转成可打分、可标注假设的情景表：受影响的业务线、成本与需求迁移方向、准备动作与观察指标，避免凭体感做扩张或收缩决策。

## 使用范围

- 优先处理平台、政策与多渠道任务；从专项证据卡选择与当前对象和问题直接相关的主题。
- 集合名称用于维护文件归属，不限制用户要求的交叉验证。其他来源与业务域的证据须分别标注，再按同口径比较。
- 本 Skill 可独立使用，不依赖仓库中的私有语义稿。保留去标识化边界，不恢复原素材身份或逐条映射。

## 适用任务

- 第二平台或新站点进入评估
- 关税与免税政策变化的情景推演
- 企业购与新兴站点机会筛选
- 站外与多平台流量溢出实验设计

## 开始前要拿到

- 现有业务线与履约模式（FBA、海外仓、直邮小包、全托管）
- 各业务线的成本结构与关税占售价比例
- 候选平台或站点的公开宏观数据与平台地位
- 自家类目在候选平台的需求代理数据
- 站内广告是否已触顶的证据

缺少字段时明确标为 `UNKNOWN` 或 `NEEDS_EVIDENCE`，不要补造数据。

## 不可妥协的边界

- 本 Skill 来自去标识化语义转译，不保留或推断素材来源身份，也不把素材观点冒充 Amazon 当前政策。
- 产品事实、账户事实和 Amazon 一方报告优先；第三方数据必须标明 Provider、站点、日期、样本和估算口径。
- 不捏造销量、搜索量、成本、合规状态、产品属性、评论、平台通知或执行结果。
- 默认提供诊断或草案。写入前展示对象、旧值、新值、影响、停止线与回退，核对用户已有授权是否覆盖对象、动作与预算；范围已明确授权时继续执行并回读核验，只有未覆盖或扩大的范围才请求批准。
- 平台规则、费率、界面和资格会变化；执行前复核当前官方文档与后台状态。
- 税率、起征额、执行日期与平台体量比较均为历史快照，不得写成当前事实。
- 跨平台合规底线一致：仿牌与假货在任何平台都不可接受。

## 工作流

1. 列出业务线与履约模式，标注每条线对政策变化的暴露程度。
2. 用体量、用户粘性、卖家密度、规则稳定性、首单难度五维评估候选平台，逐项标注证据类型。
3. 推演需求迁移方向与涨价滞后，设定观察指标（同行价格、类目销量）。
4. 识别企业购或新站点的目标行业与前置合规设置。
5. 站内触顶时设计站外或跨平台溢出实验，用专属追踪衡量增量。
6. 把全部数字标为历史快照或估算，写明复核日期。

## 专项路由

- **第二平台进入**：五维打分，并用主站已验证流程评估迁移的边际成本；早期‘搬运即出单’窗口视为一次性。
- **关税与免税情景**：按履约模式分层评估影响，先暂停高风险小包业务观望，海外仓与 FBA 照常补货。
- **新兴站点与企业购**：用宏观数据与平台地位打分，锁定企业买家行业并完成税务声明等前置设置。
- **内容平台与站外**：内容平台爆发强但备货风险高，多平台库存共享才能分摊；站外增量用专属追踪衡量。
- **小体量平台选品**：主站冷门品在小平台可能没有需求，跨平台复用前重新估算规模。

## 必须交付的结果

- 业务线暴露度表
- 候选平台或站点评分表（证据类型标注）
- 政策情景推演与观察指标
- 企业购或新站点前置清单
- 站外或多平台实验方案与追踪方式

结尾列出站点、时间窗、数据口径、证据、假设、缺口、风险、下一步和所有待批准动作。证据不足时写 `HOLD`，不得包装成可直接执行。
