# Amazon 蓝海假设验证 Playbook

## 适用问题

Use for 蓝海选品、低评论高销量、新品异军突起、差异化机会、真假蓝海. This is a pre-screen, not a sourcing decision.

## 输入证据

- 目标 marketplace、类目、价格带、上架时间与运营模式
- 候选品与同购买意图可比样本的销量、评论、价格和上架时间
- 关键词需求、历史趋势、广告依赖、同款密度和品牌集中度
- 采购、头程、平台费、退货、仓储、交期和合规/IP 基础信息

## 决策路径

1. 从增长窗口和真实购买任务出发定义市场，不以单个爆款代替需求。
2. 拆解候选品高销量来源：功能、尺寸、组合、价格、促销、品牌或流量结构。
3. 检查低评论样本能否持续获得销量，而不是只看头部。
4. 核对历史趋势、关键词自然可见度、上架时间与异常评论变化。
5. 只有差异化理由、利润和供应链都可解释时才进入正式调研。

## 经验假设与降级规则

- 异常只标为红旗，不在无证据时指控竞品违规。
- 跨平台灵感必须回到目标 Amazon 站点验证需求与合规。

- 出现固定阈值、平台算法解释或因果结论时，改为待验证假设，并用当前站点与账户数据校准。
- 数据源冲突时保留各自口径，不取没有依据的平均数，也不选择更好看的结果。
- 第三方工具不可用、额度不足或 schema 改变时，记录缺口并停止；不得伪造调用结果。

## 输出检查

- 蓝海证据卡
- 销量成因拆解
- 异常红旗
- 进入调研条件
- 每项建议都能回指当前任务中的证据或明确假设。
- 对未授权的线上变更保留草案；用户已有授权覆盖明确对象、动作与预算时可执行，并记录实际结果与回读证据。
