# Amazon 精铺组合经营 Playbook

## 适用问题

Use for 精铺选品和运营、多SKU小批量、单品盈利平衡、组合备货. Not for indiscriminate catalog flooding.

## 输入证据

- 目标 marketplace、类目、价格带、上架时间与运营模式
- 候选品与同购买意图可比样本的销量、评论、价格和上架时间
- 关键词需求、历史趋势、广告依赖、同款密度和品牌集中度
- 采购、头程、平台费、退货、仓储、交期和合规/IP 基础信息

## 决策路径

1. 为每个 SKU 设定最小利润、最大滞销库存和可接受销量区间。
2. 优先考虑存在组合、数量或风格切片且不完全标准化的产品。
3. 用趋势和可比低评论样本估算保守销量，而不是追逐头部。
4. 广告只验证最精准意图，未过盈利门槛的 SKU 不持续烧量。
5. 组合层面控制补货、现金占用和清仓风险，定期淘汰弱 SKU。

## 经验假设与降级规则

- 产品数量不是优势本身；每个 SKU 仍需合规、IP 和供应链审核。
- 不采用固定店铺订单上限作为组合规划依据。

- 出现固定阈值、平台算法解释或因果结论时，改为待验证假设，并用当前站点与账户数据校准。
- 数据源冲突时保留各自口径，不取没有依据的平均数，也不选择更好看的结果。
- 第三方工具不可用、额度不足或 schema 改变时，记录缺口并停止；不得伪造调用结果。

## 输出检查

- SKU 组合矩阵
- 单品风险上限
- 广告最小验证包
- 补货淘汰规则
- 每项建议都能回指当前任务中的证据或明确假设。
- 对未授权的线上变更保留草案；用户已有授权覆盖明确对象、动作与预算时可执行，并记录实际结果与回读证据。
