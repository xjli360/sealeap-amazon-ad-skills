# Amazon 商品运营难度评估 Playbook

## 适用问题

Use for 产品好不好运营、评论少能卖多少、该发多少货、头部销量高但新品难做. Do not treat heuristic ratios as guarantees.

## 输入证据

- 目标 marketplace、类目、价格带、上架时间与运营模式
- 候选品与同购买意图可比样本的销量、评论、价格和上架时间
- 关键词需求、历史趋势、广告依赖、同款密度和品牌集中度
- 采购、头程、平台费、退货、仓储、交期和合规/IP 基础信息

## 决策路径

1. 定义同站点、同意图、价格与形态接近的可比样本，排除明显异常项。
2. 按评论成熟度分层，比较各层销量分布与头部基线。
3. 补充广告依赖、退货、店铺历史、价格和配送方式等影响因素。
4. 从低评论层的保守可实现销量反推库存盈利区间。
5. 输出区间和敏感性分析，不输出单点成功概率。

## 经验假设与降级规则

- 店铺历史影响流量只能作为可能因素，不能声称存在固定订单上限。
- 评论层级统计易受合并变体、促销、站外流量和估算误差污染。

- 出现固定阈值、平台算法解释或因果结论时，改为待验证假设，并用当前站点与账户数据校准。
- 数据源冲突时保留各自口径，不取没有依据的平均数，也不选择更好看的结果。
- 第三方工具不可用、额度不足或 schema 改变时，记录缺口并停止；不得伪造调用结果。

## 输出检查

- 可比样本说明
- 难度分层表
- 库存盈亏区间
- 数据质量红旗
- 每项建议都能回指当前任务中的证据或明确假设。
- 对未授权的线上变更保留草案；用户已有授权覆盖明确对象、动作与预算时可执行，并记录实际结果与回读证据。
