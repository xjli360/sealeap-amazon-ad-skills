# Amazon 广告架构设计 Playbook

## 适用问题

Use for 广告架构怎么搭、有精准词或泛词怎么分、无关键词产品、自动和ASIN投放. Not for blaming architecture for every conversion issue.

## 输入证据

- marketplace、店铺、ASIN/SKU、广告类型和目标
- 同口径的 Campaign、Targeting、Search Term、Placement 与 Advertised Product 报告
- 售价、优惠、COGS、Amazon 费用、退款与目标贡献利润
- 库存、Buy Box、Listing、评论和同期市场事件

## 决策路径

1. 先排除产品、价格、页面与评论竞争力问题，再设计流量结构。
2. 明确属性词产品：精准核心词与属性词根探索分层。
3. 场景型泛流量产品：场景词、相似 ASIN 和自动发现分别建样本。
4. 无明确关键词产品：从可替代竞品商品页和自动流量开始验证。
5. 为每层定义目的、预算、位置、成功指标和停止条件。

## 经验假设与降级规则

- 架构影响流量获取和可解释性，不会自动提高产品转化。
- 自然排名阈值和历史权重只用于筛选，不能当算法规则。

- 出现固定阈值、平台算法解释或因果结论时，改为待验证假设，并用当前站点与账户数据校准。
- 数据源冲突时保留各自口径，不取没有依据的平均数，也不选择更好看的结果。
- 第三方工具不可用、额度不足或 schema 改变时，记录缺口并停止；不得伪造调用结果。

## 输出检查

- 流量类型诊断
- 分层架构图
- 每层实验契约
- 转化问题排除表
- 每项建议都能回指当前任务中的证据或明确假设。
- 对未授权的线上变更保留草案；用户已有授权覆盖明确对象、动作与预算时可执行，并记录实际结果与回读证据。
