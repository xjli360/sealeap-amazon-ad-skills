# Amazon 店铺订单承载扩张

## 目标

把货架宽度与店铺真实承载能力分开，按订单稳定性、利润、库存和团队容量分阶段扩充 SKU。

## 适用任务

- 诊断新品增加后老品订单被分流。
- 制定首批产品和后续扩品节奏。
- 评估团队、现金流和库存是否能承接下一档规模。

## 开始前要拿到

- 按日/周拆分的 SKU 订单、流量、转化率和广告数据。
- 新品上架、老品断货、价格与促销变动时间线。
- 各 SKU 贡献利润、库存周转、采购与补货约束。
- 团队在采购、视觉、运营和客服上的实际容量。

缺少字段时列出证据缺口，并把相关结论标为 `FACT`、`ESTIMATE`、`ASSUMPTION` 或 `UNKNOWN`；不要补造数据。

## 不可妥协的边界

- 第三方数据均为估算或代理证据；Amazon 一方报告、后台实时字段和产品事实优先。
- 经验阈值只能作为可调起点，必须展示敏感性分析，不能写成 Amazon 官方规则。
- 不得捏造销量、搜索量、CPC、CVR、成本、认证、产品属性或消费者需求。
- 默认提供诊断或草案。写入前展示对象、旧值、新值、影响、停止线与回退，核对用户已有授权是否覆盖对象、动作与预算；范围已明确授权时继续执行并回读核验，只有未覆盖或扩大的范围才请求批准。
- 不输出或保存素材来源身份、账号、链接、作品编号、互动数据、原始话术或其他可反查来源的线索。
- 不得把相关性误写成平台流量配额因果。
- 扩品方案不得忽略库存和固定成本的非线性增长。

## 工作流

### 1. 建立基线

按上新前后窗口比较总订单、自然/广告流量和贡献利润，不只看单个新品是否出单。

### 2. 识别分流

检查老品下降是否与新品上架同步，并排除断货、季节、价格、Buy Box 和广告预算迁移等混杂因素。

### 3. 分批扩品

以可管理的小批产品起步，保留淘汰和补位机制；只有稳定订单与利润后才扩大下一批。

### 4. 核对承载

同步检查现金、首批库存、补货周期、广告预算和人员工时，防止 SKU 数先于能力膨胀。

### 5. 设升档门

当总订单、利润、周转和执行 SLA 连续达标时升档；若分流或复杂度陡升，暂停扩张并修复瓶颈。

## 判断标准

- 所谓店铺订单上限是经营观察假设，不是 Amazon 官方算法或固定配额。
- 首批 5–10 个、每 2–3 个月增加一批只能作为低风险起点，必须随资金和能力调整。
- 规模以稳定且有利润的总订单衡量，不以 Listing 数量衡量。

## 必须交付的结果

- 订单承载趋势图
- SKU 分流诊断表
- 保留/淘汰/补位清单
- 下一批扩品门槛
- 资源容量与风险说明

结尾列出站点、数据窗口、证据来源、关键假设、缺口、风险、下一步和所有待批准动作。证据不足时写 `HOLD`，不得包装成可直接执行。

执行细节、证据字段和质量检查见 [references/playbook.md](references/playbook.md)。
