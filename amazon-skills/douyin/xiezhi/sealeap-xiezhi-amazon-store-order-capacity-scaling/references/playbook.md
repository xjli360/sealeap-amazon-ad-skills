# Amazon 店铺订单承载扩张执行手册

## 核心模型

把货架宽度与店铺真实承载能力分开，按订单稳定性、利润、库存和团队容量分阶段扩充 SKU。

## 工作卡

| 步骤 | 动作 | 做法 | 留痕 |
|---|---|---|---|
| 1 | 建立基线 | 按上新前后窗口比较总订单、自然/广告流量和贡献利润，不只看单个新品是否出单。 | 记录证据、判断与停止条件 |
| 2 | 识别分流 | 检查老品下降是否与新品上架同步，并排除断货、季节、价格、Buy Box 和广告预算迁移等混杂因素。 | 记录证据、判断与停止条件 |
| 3 | 分批扩品 | 以可管理的小批产品起步，保留淘汰和补位机制；只有稳定订单与利润后才扩大下一批。 | 记录证据、判断与停止条件 |
| 4 | 核对承载 | 同步检查现金、首批库存、补货周期、广告预算和人员工时，防止 SKU 数先于能力膨胀。 | 记录证据、判断与停止条件 |
| 5 | 设升档门 | 当总订单、利润、周转和执行 SLA 连续达标时升档；若分流或复杂度陡升，暂停扩张并修复瓶颈。 | 记录证据、判断与停止条件 |

## 启发式参考

- 所谓店铺订单上限是经营观察假设，不是 Amazon 官方算法或固定配额。
- 首批 5–10 个、每 2–3 个月增加一批只能作为低风险起点，必须随资金和能力调整。
- 规模以稳定且有利润的总订单衡量，不以 Listing 数量衡量。

这些阈值只能用于提出和排序假设。输出必须同时给出参数变化后的结论是否改变。

## 证据台账字段

- `claim`：要支持的判断。
- `evidence_type`：一方事实、第三方估算、公开证据、用户输入或假设。
- `provider/tool`：数据提供方与实时发现的工具名；不记录密钥。
- `marketplace/window/sample`：站点、时间窗和样本量。
- `value/unit/definition`：数值、单位和字段定义。
- `confidence/limitations`：可信度、偏差方向和缺口。
- `decision/owner/next_check`：当前结论、责任人和下一次复核点。

## 质量检查

- 直接竞品由相同购买对象、场景、核心属性和价格带定义，而不是搜索结果总数。
- 同一表格内销量、点击、访客、订单、父体与子体口径保持一致。
- 对异常评价、合并变体、极端促销、站外流量和季节事件作单独标记。
- 任何公式展示输入、单位、时间窗和敏感性区间。
- 每个 GO 建议同时给出失败条件、止损和下一步验证。
- 采购、发布或账户写操作仍需独立批准。
