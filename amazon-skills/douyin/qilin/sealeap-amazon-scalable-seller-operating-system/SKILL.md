# Amazon 团队规模化运营系统

## 目标

把个人经验转化为团队可复制的组合管理系统，同时为高水平人员保留判断空间，为普通岗位守住执行下限。

## 适用任务

- 运营从少量 SKU 扩展到产品组合。
- 老板需要判断运营、产品和广告能力。
- 设计 SOP、助理分工、激励与资源分配。

## 开始前要拿到

- 团队角色、每人管理 SKU、任务耗时和技能评估。
- 产品组合的利润、阶段、成功率、库存和预算。
- 现有 Listing、广告、新品验证和复盘流程。

缺失的数据要明确列为缺口，并把结论标成事实、估算或假设；不要补造数字。

## 不可妥协的边界

- 不把单个公司的销售额、人效或成功率当作普遍基准。
- 资源向绩效者倾斜时必须控制幸存者偏差并保障公平、合规和可解释性。
- SOP 不能替代专业判断，也不能以规模为由降低产品或合规标准。
- 当前 Amazon 官方政策、帮助页、账户资格和后台实际字段优先于本 Skill 中的经验框架；规则可能变化时先核验。
- 默认提供诊断或草案。写入前展示对象、旧值、新值、影响、停止线与回退，核对用户已有授权是否覆盖对象、动作与预算；范围已明确授权时继续执行并回读核验，只有未覆盖或扩大的范围才请求批准。
- 不输出原素材的创作者身份、账号、链接、视频编号或可反查线索；当前业务证据的官方来源、采集时间和口径仍需保留。

## 工作流

### 1. 画出运营系统

从选品、开发、Listing、合规、广告、库存到复盘，标出决策点、责任人和交接物。

### 2. 测算容量

按任务频率和复杂度计算每个角色可承载的 SKU，识别可交给助理或自动化的重复工作。

### 3. 分层能力

用实际案例和结果区分专家、独立执行者和需辅导人员，避免只看工龄或销售额。

### 4. 建立 SOP 下限

为研究、Listing、上线检查、广告测试和复盘定义输入、步骤、质量门槛与异常升级。

### 5. 设计组合治理

按产品阶段分配预算和人力，用实验成功率、贡献利润和学习价值决定继续、加码或退出。

### 6. 对齐激励

让收益与可控贡献、利润和长期质量相关，公开计算口径并避免临时改变规则。

## 判断标准

- 每个 SOP 有负责人、输入、输出和升级条件。
- 容量提升没有牺牲利润、库存健康或合规。
- 优秀人员的自由度与风险责任相匹配。

## 必须交付的结果

- 端到端运营流程图。
- 岗位容量与技能矩阵。
- 关键 SOP 目录和质量门槛。
- 产品组合资源分配与激励原则。

结尾列出数据窗口、关键假设、证据缺口、风险和下一步；如包含待执行动作，单独放在“待批准变更”中。
