# Amazon FBA 瑕疵库存排查

## 目标

快速确定不可售库存的状态链和证据缺口，争取在自动移除前获得明确原因、恢复或可控处置。

## 适用任务

- 新品入仓后直接显示瑕疵或不可售。
- 合规审核通过但库存状态未恢复。
- 客服只给模板回复或自动移除临近。

## 开始前要拿到

- 站点、ASIN、SKU、FNSKU、货件、FC、数量和首次异常时间。
- 标签样张、箱唛、Transparency 状态、入仓记录、Listing 变更历史。
- 合规通知、案例编号、回复记录和自动移除截止时间。

缺失的数据要明确列为缺口，并把结论标成事实、估算或假设；不要补造数字。

## 不可妥协的边界

- 不要在原因不明时反复修改 Listing、重贴标或创建新货件，以免破坏证据。
- 不使用切换站点、隐藏按钮或其他界面漏洞作为标准处置方案。
- 所有客服陈述保持事实一致，不并行提交相互矛盾的 case。
- 当前 Amazon 官方政策、帮助页、账户资格和后台实际字段优先于本 Skill 中的经验框架；规则可能变化时先核验。
- 默认提供诊断或草案。写入前展示对象、旧值、新值、影响、停止线与回退，核对用户已有授权是否覆盖对象、动作与预算；范围已明确授权时继续执行并回读核验，只有未覆盖或扩大的范围才请求批准。
- 不输出原素材的创作者身份、账号、链接、视频编号或可反查线索；当前业务证据的官方来源、采集时间和口径仍需保留。

## 工作流

### 1. 冻结证据

导出库存状态、数量、事件时间、货件和合规记录，保存每次客服回复与案例编号。

### 2. 分类根因

依次检查标签或 FNSKU、错仓或货件、Transparency、商品状况投诉、Listing 重大变化、合规释放不同步和系统错误。

### 3. 核对商品身份

确认当前标题、属性、包装与入仓实物一致；如曾大改，形成变更时间线和实物证明。

### 4. 提交单一证据包

在英文或站点支持语言中列出事实、已通过状态、受影响库存和明确诉求，要求给出具体 defect reason code 或恢复依据。

### 5. 管理时限与升级

记录自动移除期限；如审核或平台延误，依据当前官方流程申请延长或升级，不重复轰炸 case。

### 6. 选择处置

只有恢复不可行且原因确认后，比较移除、翻新、重新贴标或销毁的成本和风险，并等待人工批准。

## 判断标准

- 库存数量和状态来自当前后台证据。
- 根因假设逐项排除，不默认平台或恶意行为。
- 任何移除、销毁或重新入仓都需要明确批准。

## 必须交付的结果

- 异常时间线和证据清单。
- 根因排查矩阵。
- 支持 case 草稿与升级路径。
- 恢复或处置的成本对比。

结尾列出数据窗口、关键假设、证据缺口、风险和下一步；如包含待执行动作，单独放在“待批准变更”中。
