# Amazon 专利投诉响应

## 目标

在截止时间内保全证据、理解投诉基础并让专业律师选择法律路径，同时准备一致、真实的平台材料。

## 适用任务

- ASIN 因发明、实用或外观专利投诉下架。
- 上线前检索未发现但后来出现权利。
- 需要比较申诉、和解、改款或无效程序。

## 开始前要拿到

- 绩效通知全文、投诉编号、权利人信息、专利号、站点和截止时间。
- 产品开发记录、首售时间、设计图、供应合同、样品和既有检索。
- 受影响销量、库存、利润、替代品和业务中断成本。

缺失的数据要明确列为缺口，并把结论标成事实、估算或假设；不要补造数字。

## 不可妥协的边界

- 不得提交虚假 POA、伪造设计记录、隐瞒材料事实或威胁投诉方。
- 专利范围与无效判断必须由相应法域的合格律师分析。
- 恢复一次不代表对方不能再采取行动，也不承诺申诉结果。
- 当前 Amazon 官方政策、帮助页、账户资格和后台实际字段优先于本 Skill 中的经验框架；规则可能变化时先核验。
- 默认提供诊断或草案。写入前展示对象、旧值、新值、影响、停止线与回退，核对用户已有授权是否覆盖对象、动作与预算；范围已明确授权时继续执行并回读核验，只有未覆盖或扩大的范围才请求批准。
- 不输出原素材的创作者身份、账号、链接、视频编号或可反查线索；当前业务证据的官方来源、采集时间和口径仍需保留。

## 工作流

### 1. 冻结事件

保存通知、详情页、产品样品、时间线、库存和销售影响；避免删除会影响证据的文件。

### 2. 核验权利

让律师确认法域、专利状态、权利要求或图示、权利人和投诉是否与商品对应。

### 3. 做技术比对

把被诉产品特征逐项映射到权利要求或设计视图，记录相同、不同和需专家判断项。

### 4. 比较路径

与律师评估不侵权意见、设计绕开、许可或和解、停售清货及无效挑战的时间、成本和风险。

### 5. 准备平台材料

按通知要求提交身份、事实、证据和明确诉求；法律意见需由律师签发并保持与外部策略一致。

### 6. 建立预防闭环

未来新品做检索、持续监测待审权利、保存独立开发记录，并从功能、结构与外观多角度规划自身 IP。

## 判断标准

- 所有期限和法域已确认。
- 平台陈述与律师意见一致且可举证。
- 业务恢复方案考虑库存、现金和再次投诉风险。

## 必须交付的结果

- 事件时间线与证据保全清单。
- 律师问题清单和技术比对表。
- 路径成本风险矩阵。
- 平台申诉材料清单与预防计划。

结尾列出数据窗口、关键假设、证据缺口、风险和下一步；如包含待执行动作，单独放在“待批准变更”中。
