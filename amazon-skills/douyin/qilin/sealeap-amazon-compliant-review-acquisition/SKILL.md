# Amazon 合规评价获取

## 目标

在不操纵评价的前提下，通过官方项目、真实订单和更好的产品体验逐步建立可信反馈。

## 适用任务

- 高客单商品评价增长慢。
- 评估 Vine 成本与库存投入。
- 服务商提出付费测评、种子链接、跨站同步或僵尸链接。

## 开始前要拿到

- 站点、品牌与 ASIN 的 Vine 或其他官方项目资格。
- 售价、样品成本、库存、真实订单量和 Request a Review 流程。
- 当前评论政策、变体规则和客户体验问题。

缺失的数据要明确列为缺口，并把结论标成事实、估算或假设；不要补造数字。

## 不可妥协的边界

- 拒绝付费好评、返现、指定星级或内容、亲友员工评论、无购买直评和评价门控。
- 不得用种子链接、僵尸 ASIN、不相关变体或跨站点安排评论来共享评价。
- 客服不能只向满意客户索评，也不能把补偿与评论修改绑定。
- 当前 Amazon 官方政策、帮助页、账户资格和后台实际字段优先于本 Skill 中的经验框架；规则可能变化时先核验。
- 默认提供诊断或草案。写入前展示对象、旧值、新值、影响、停止线与回退，核对用户已有授权是否覆盖对象、动作与预算；范围已明确授权时继续执行并回读核验，只有未覆盖或扩大的范围才请求批准。
- 不输出原素材的创作者身份、账号、链接、视频编号或可反查线索；当前业务证据的官方来源、采集时间和口径仍需保留。

## 工作流

### 1. 核对官方资格

检查当前站点的 Vine、Request a Review 和品牌工具资格、费用、库存要求与限制。

### 2. 测算真实成本

按样品、配送、项目费、机会成本和预期非保证回评计算区间，不承诺星级或数量。

### 3. 提高体验成功率

从质检、包装、安装、说明、配件和售后减少负面体验，但不干预评价倾向。

### 4. 建立中立请求

对符合条件的订单使用 Amazon 允许的统一、中立流程，不筛选客户，不自定义诱导文案。

### 5. 验证变体合法性

仅让真实同款的合法变体共享页面体验；任何合并先核对当前类目规则。

### 6. 监控质量而非造量

跟踪评论主题、退货和产品缺陷，把反馈用于迭代；增长慢时接受真实节奏。

## 判断标准

- 每条获评路径有官方依据和资格状态。
- 没有报酬、评价倾向控制或不相关合并。
- 成本模型把回评率作为不确定变量。

## 必须交付的结果

- 合规路径资格矩阵。
- Vine 或官方项目成本情景。
- 中立请求与客户体验 SOP。
- 明确拒绝的高风险方案清单。

结尾列出数据窗口、关键假设、证据缺口、风险和下一步；如包含待执行动作，单独放在“待批准变更”中。
