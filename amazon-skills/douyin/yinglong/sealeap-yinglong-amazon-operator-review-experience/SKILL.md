# Amazon 跨境经营复盘：经营经验

## 目标

围绕经营经验，将经验判断转成可验证的问题，识别适用前提、替代解释和可迁移的经营动作。

## 使用范围

- 优先处理跨境经营复盘任务；从专项证据卡选择与当前对象和问题直接相关的主题。
- 集合名称用于维护文件归属，不限制用户要求的交叉验证。其他来源与业务域的证据须分别标注，再按同口径比较。
- 本 Skill 可独立使用，不依赖仓库中的私有语义稿。保留去标识化边界，不恢复原素材身份或逐条映射。

## 适用任务

- 经验假设卡
- 适用边界
- 验证计划

## 开始前要拿到

- 要解决的经营问题和适用场景。
- 已有事实、数据与限制。
- 可逆动作、成本与责任人。
- 成功、停止和复核条件。

缺少字段时明确标为 `UNKNOWN` 或 `NEEDS_EVIDENCE`，不要补造数据。

## 不可妥协的边界

- 本 Skill 来自去标识化语义转译，不保留或推断素材来源身份，也不把素材观点冒充 Amazon 当前政策。
- 产品事实、账户事实和 Amazon 一方报告优先；第三方数据必须标明 Provider、站点、日期、样本和估算口径。
- 不捏造销量、搜索量、成本、合规状态、产品属性、评论、平台通知或执行结果。
- 默认提供诊断或草案。写入前展示对象、旧值、新值、影响、停止线与回退，核对用户已有授权是否覆盖对象、动作与预算；范围已明确授权时继续执行并回读核验，只有未覆盖或扩大的范围才请求批准。
- 平台规则、费率、界面和资格会变化；执行前复核当前官方文档与后台状态。

## 工作流

1. 把经历或观点改写成可验证的问题，而非直接当作规律。
2. 列出适用前提、反例、数据缺口和可迁移部分。
3. 设计成本最低、可逆的验证动作。
4. 记录结果、意外影响和是否需要专业复核。
5. 只把重复验证有效的部分沉淀为团队流程。

## 专项路由

- **经营经验**：把个人观点降级为待验证假设，并明确适用前提和反例。

完整的 1 张主题证据卡见 [references/topic-cards.md](references/topic-cards.md)；1 种原有组合见 [references/scenario-patterns.md](references/scenario-patterns.md)。

## 必须交付的结果

- 经验假设卡
- 适用边界
- 验证计划
- 风险与反例
- 复盘结论

结尾列出站点、时间窗、数据口径、证据、假设、缺口、风险、下一步和所有待批准动作。证据不足时写 `HOLD`，不得包装成可直接执行。

执行细节、证据字段和质量检查见 [references/playbook.md](references/playbook.md)。
